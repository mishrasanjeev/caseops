# CaseOps agent instructions

- A clean filesystem audit needs complete, unique root-present inventories and
  final path/metadata reconciliation. Charge both observations to the existing
  entry/byte/deadline limits; an empty successful command or a file inserted
  after discovery cannot become a complete zero-copy result.
- Public fixture staging must transfer the descriptor-verified bytes. Keep the
  bounded verified buffer through the exclusive device write; reopening its
  pathname can disclose replacement bytes before a later hash refusal.
- Fixture provenance must bind immutable configuration bytes, not a mutable
  gateway configuration path that a normal ledger reset replaces. Validate that
  snapshot in both producer and consumer and retain the original run separately.

- A SwiftUI control embedded in a React Native safe-area container must not
  apply that container inset again. Compare native button and host frames,
  visibility and hittability after scrolling; a visible label does not prove
  its control is tappable. Preserve keyboard insets when adjusting the host.

- An iOS picker URI returned without the SDK's cache copy is not guaranteed
  immediately readable. Use the documented cache-copy contract, validate the
  returned direct-child path, size and ownership before staging, and purge every
  owned private copy. The SDK's native copy precedes JavaScript size validation.
  Preserve the OS-managed Inbox parent while purging validated owned files;
  directory preservation alone did not repair the observed unreadable URI.
  Prove repeated select/clear/select on the native build without a host byte-read
  that can prewarm the provider under investigation.
- A rejected busy command must not run the first command's completion cleanup.
  Hold a synchronous interaction lease outside React's render cycle, read live
  state in retained Clear/Choose/leave callbacks, and exercise rapid input with
  the actual controller, staging and provider cleanup composed together.
- WebdriverIO element click wrappers can refetch and reexecute a stale click
  even with transport retries disabled. Dispatch native clicks through the
  driver's single protocol command; preserve stale/lost acknowledgements and
  never silently replay a possible mutation.

- Passive native diagnostics must return the original promise unchanged; adding
  an async wrapper or await can change the race being investigated. Keep fixed,
  secret-free operation labels behind the explicit QA flag and retain the failed
  candidate separately from later diagnostic builds.
- Descriptor identity must remain portable without weakening file ownership.
  Windows can report lstat.dev=0 while fstat.dev is nonzero; require the same
  inode and a regular, non-symlink pathname on every platform, and compare device
  IDs on platforms that expose them consistently. Simulated metadata is not
  actual Windows acceptance.

- Native acceptance is not a platform-named JavaScript export. Bind the actual
  APK or Simulator app, source fingerprint, backend revision and complete Appium
  inventory independently for Android and iOS. A stable wrapper can contain
  experimental native components; inspect the actual pinned theme/dependencies.
- Native save preflight does not close a lifecycle race. Carry the observed
  lifecycle version through the request DTO and check it under the same parent
  lock as the mutation, including close/reopen between read and submit.

- Verification isolation belongs on each actual HTTP constructor, including
  curl, urllib, container fetch, readiness and signed verification clients.
  A Playwright fixture cannot supply another client's no-paid marker. Regress
  the received headers/native argument array on happy, failed and retried
  requests; preserve TLS, authentication, payloads and original time bounds.
  An unmarked public metadata read is a protocol deviation, not proof of a
  billable provider call. Retain it and replay the marked boundary explicitly.

- Workstation gates must own their dependency installation exclusively. Do
  not run a host npm install/ci while Vitest, a build or another gate uses that
  same worktree's node_modules. Activate the pinned Node runtime first, finish
  installation, then run verification. Preserve interrupted or mixed-runtime
  reports as incomplete and replay the full frozen inventory without retries.

- A dependency override is not a resolved security repair. Reconcile every
  nested locked and installed identity after targeted regeneration; npm can
  retain an older transitive copy even after its override changes. Preserve
  parser-level reproductions and exact-version licence provenance alongside
  fresh full-source audit, Docker and deployed-workflow evidence.

- A dated asynchronous-job check must own its bounded completion contract,
  not silently inherit a different local or production UI assertion timeout.
  Correlate the failed attempt with persisted job timestamps before diagnosis.
  Keep finite serial status reads, per-read deadlines, immediate terminal-failure
  rejection, exact job identity, single enqueue and byte-exact artifact checks.
  Do not relax interactive budgets or erase the original failed release evidence.
- A new root-level helper imported by colocated web units must be in the builder
  COPY closure, both explicit context allowlists and the deploy dirty-input fence.
  Run the existing dynamic closure checks before freezing the candidate. Adding
  a native reporter regression also changes its independent expected case count;
  preserve exact counts and zero-failure/skip/cancellation/todo assertions.

- A browser test's name is not workflow evidence. A drafting test that stops
  after requesting changes does not prove regeneration, approval or finalization.
  Assert every named transition, the exact current revision, retained earlier
  versions and post-reload state. Reconcile mobile project selection separately.
- A contact-update API does not make an existing verified client's profile
  editable. Prove the actual prefilled editor, dirty-only null-clearing payload,
  persisted reload and unchanged KYC evidence, identity and Matter associations.
  A citation catalogue match likewise does not prove legal proposition accuracy;
  keep zero-citation approval fail-closed and distinguish source recovery from
  a guarantee that regeneration will produce a legally valid draft.
- Frontend tests can execute repository-level Playwright configuration and
  fixtures. Their source guard must include those actual inputs, not only
  apps/web. An unchanged narrow fingerprint cannot certify a run that read an
  intermediate root configuration. Preserve the failure and rerun the complete
  intended inventory after all input writers close.
- Desktop touchscreen hardware does not establish a Playwright context's touch
  mode. Select tap versus click from the configured project's hasTouch setting,
  and independently prove mobile viewport, isMobile, touch and visible targets.
  Do not lower target-size assertions when they expose a genuine small link.
- A rejected stale-tab approval must refresh the authoritative current draft
  revision without replaying approval. Prove the actual browser POST returns
  the expected safety rejection, no approval audit is created, and the stale
  positive revision is replaced by the current blocked revision.
- A Docker removal acknowledgement is not proof of container absence. Verify
  the exact invocation-owned name under one bounded cleanup deadline, preserve
  the original scan failure, and reject transport errors or ambiguous output.
  A failed harness is neither a detected secret nor a completed secret scan.
- A frozen report clock must also govern its signed cursor validation. A fixed
  issuance time paired with real JWT time eventually expires pagination tests.
  Scope the test clock to report decoding, preserve real authentication time,
  and prove before/at/after expiry plus signature, audience and required claims.
  Never extend production TTL or disable verification to repair this fixture.
  A temporary JWT-module clock patch is process-global, not thread-local:
  serial report-call evidence does not authorize reuse with concurrent
  unrelated authentication decoding without separate isolation proof.
- An IP pleading's approval control needs a successful, idle validation for
  that exact current version, not merely the absence of a negative response.
  Loading, missing, failed or mismatched validation and failed recovery reads
  remain unavailable. Regress both list-backed and deep-linked stale tabs.
- Passing Vitest and E2E TypeScript do not type-check component tests. Compile
  the web project before an expensive full Docker gate. Testing Library role
  locators do not accept Playwright's exact option; use anchored name matchers
  without weakening exact control identity.

- An ORM migration must update both the reviewed data-class map and its
  compiled governance projection before release tests. Render and validate
  with the canonical generator, then replay the complete affected PostgreSQL
  journey; a stale-projection denial is not a reason to disable preservation.
- Docker acceptance must measure the Docker filesystem's available bytes and
  inodes before builds and database/browser phases. Host-drive free space and
  aggregate image sizes do not establish headroom. Retain ENOSPC failures as
  incomplete/failed evidence, recover only explicitly owned or reviewed unused
  resources, then run a complete replacement gate without weakening assertions.
- Capacity-probe fixtures must reflect the canonical Compose mounts, including
  its read-only PostgreSQL initialization script. Probe only the independently
  verified owned data volume, never all inherited mounts. Exercise every probe
  stage on the real isolated Compose service before launching the full gate.

- A browser response waiter observes headers, not necessarily a readable body.
  Before reloading a page with a same-URL API fetch, finish the initial body and
  prove its visible render; bind the reload to a new request and await completion
  before parsing. Keep body-retrieval failures distinct from malformed JSON and
  preserve payload, reload and UI assertions. A discarded decoder exception is
  not evidence that the server returned invalid data.

- Reviewed browser inventories have independent Python and frontend source
  contracts. After adding a journey, reconcile its exact literal identity and
  per-role counts in both languages, not only the runner count. Keep whole
  inventory equality and run the complete independent source-inventory module.
- Test cleanup must use the uniquely admitted canonical identity, not an
  unnormalized request value. Assert the create acknowledgement first, preserve
  the original body failure separately from cleanup failures, and mark every
  unreached journey boundary unverified. A failing finally block is not proof
  that the body passed or that persisted product data was corrupted.

- A "Recent" collection must have a server-owned chronological order and a
  unique tie-breaker before a client slices it. Database physical row order is
  not a contract. Prove distinct timestamps dominate IDs, exact timestamp ties
  are stable, and opposite already-materialized collection orders serialize to
  the same complete DTO. Keep whole-response equality and reload assertions;
  sorting only the test would hide the user-visible newest-record omission.
  A final merge sort cannot repair arbitrary membership selected by an earlier
  timestamp-only SQL LIMIT; add the unique tie-breaker before that bound and
  assert the exact included/excluded identities across the tied boundary.

- A one-time derived-state backfill does not cover old API writers still
  serving during deployment. Reproduce a successful old-column insert after
  migration on both dialects and prove immediate visibility, converted-source
  lineage and unchanged outbox bytes. Compatibility must not promote historical
  notification eligibility or undo a current-protocol exclusion or later revoke;
  a broad update trigger that resurrects an explicit false is not a valid fix.

- A retained-record read schema must match the nullable storage/API contract,
  not only mandatory fields in a new-submission form. Prove one incomplete
  legacy/commercial row cannot hide valid siblings in the same response, show
  honest missing-value labels, and keep required keys and invalid types strict.
- Scoped browser fixtures must establish their configured synthetic founder
  before report fixtures that create a provenance-only root with a random
  password. Preserve failed setup data, bootstrap the fresh local identity via
  normal APIs, and never reset a retained root or weaken authentication to make
  a guessed password work. Keep that operator prerequisite distinct from the
  canonical complete-suite fixture ordering and production owner acceptance.

- Enabling a release-owned notification purpose changes the initial queued
  state even for a no-paid synthetic admission. Reconcile dated API and visible
  readback assertions with that explicit harness policy; the no-paid marker is
  not a disabled-purpose flag. Preserve zero attempts/no transport, reload and
  role-denial checks, and independently retain disabled-purpose/no-retrofit tests.
- A browser failure before a later responsive or permission assertion leaves
  those steps unverified. Correct the original dated journey and replay its
  complete file plus the new sibling workflow, not just the first assertion.

- Public lead visibility is separate from notification eligibility. An owner
  opting into new-submission alerts must not reactivate historical outbox rows,
  old idempotency keys or admissions made while the purpose was disabled. Prove
  that boundary across configuration changes, restarts and retries. A protected
  lead read never grants tenant membership or founder billing authority; email
  transport acceptance is not inbox delivery.
- A request-local no-paid marker suppresses that invocation, not a previously
  admitted human obligation. A marked idempotent replay must leave the human
  outbox byte-equivalent and make zero provider calls; a later ordinary drain
  must still deliver exactly once. Persisted synthetic admissions remain barred
  from real transport through every background and retry path.
  Background transport must also prove the original admission request session
  ended its transaction on replay, not merely that its separate worker session
  was closed; request-scoped dependency cleanup can occur after background work.
- Before freezing a candidate, enumerate untracked files in every build/test
  scope and reconcile the sidecar's exact changed-path list. Collapsed directory
  entries can hide a page test beside its page; a green local run may otherwise
  cover a test that was never committed. Preserve a refused preflight as incomplete.
- Run the actual changed-migration preflight against canonical main before a
  long release gate. A passing inventory or governance-map check is not that
  preflight. Retained classification is committed data too: rollback refusal
  must preserve its rows, columns, indexes and revision, with fresh database proof.
- A dated downgrade rehearsal must start at its named historical boundary,
  not moving head: a newer restore-only guard can prevent the intended older
  lock, DDL or refusal from running. Keep separate actual-current-head refusal
  and full index-health proofs. Compare a historical rollback to its complete
  dated catalog, not newer model indexes; never accept the wrong guard by regex.
- Positive cross-dialect provider fixtures must retain the no-paid marker and
  explicitly admit an owned offline transport. A callback below a correctly
  closed isolation fence was never exercised; an empty observation cannot prove
  a locking defect. Regress real callback entry on both dialects and retain the
  cloud-runtime, nonlocal-origin and real-transport refusal cases.

- New dependency notices must be reconciled across every exact upload, image,
  retained-source and public-notice inventory before starting long release gates.
  A base-policy license still needs its bundled attribution; preserve historical
  exception registries and pin supplemental source bytes explicitly.

- Authenticator QR acceptance must independently decode rendered pixels, bind
  the issuer/account/secret/algorithm/digits/period to the real enrollment and
  complete actual API verification. An image existing in the DOM is not enough.
  Never use an external QR service or retain live QR/key media. Synthetic
  production renderer contracts do not certify the owner's private MFA setup.

- Native Node TLS probes belong in repository test fixtures, not inline in
  first-party web source. Preserve real default-client verification, bounded
  deadlines and loopback-only admission. Run the unchanged cross-language
  deadline inventory before expensive release gates, and include the fixture
  explicitly in any isolated frontend test snapshot.

- Integrity-sensitive runtime files must be checked and read through the same
  opened descriptor, with closure on every failure. Require both the scanner's
  analysis job and its separate alert verdict to pass. A secret-scanner finding
  on a public package digest needs exact origin-span provenance, not a broad
  path exclusion; an infrastructure failure before scanning remains incomplete.

- Dependency closure includes installed Linux/Windows inventories and shipped
  build tools outside the application lock. Recheck fresh advisory data before
  expensive gates. A compatibility rebuild must pin its official input,
  preserve runtime code/notices, reproduce deterministically and pass native
  dependency validation; an override that still fails `uv pip check` is not a
  healthy environment. Test the actual offline inference and image paths.
- Distrusting a compromised CA must be idempotent when an upstream image has
  already removed it. Preserve every other trust anchor and certificate/host
  verification; reject unknown identities or a still-trusted compromised root.
- Trust-store remediation must cover each reachable TLS runtime, not only the
  package named by an advisory. Python certifi does not update Node's bundled
  roots. Prove the effective image defaults with HTTPS and fetch controls,
  preserve hostname/certificate verification and reject additive CA overrides;
  `tls.rootCertificates` alone does not describe the selected OpenSSL store.
- Reuse the actual previously accepted executable/version for release-test
  hosts, not an advertised minimum version. Native tools can emit successful
  diagnostics on stderr; preserve the log and check the real exit status,
  including a nonzero control, rather than treating stderr text as failure.
- Compare process identity timestamps as exact UTC round-trip strings. A UTC
  DateTime and a locally parsed `Z` literal can represent the same instant but
  compare unequal before normalization. Recheck ancestry, command and creation
  identity before stopping only an owned native child; keep its cleanup parent.
- Security evidence expires when a new upstream advisory affects the frozen
  dependency set. Patch the affected lock entry, retain the failed scan and
  rebuild every shipping image; an earlier green scan is not a waiver.
- A database error response does not prove a mutation rolled back. Read the
  persisted version and audit before replaying a save; a post-commit response
  query can fail independently. Staged portfolio facts need distinct stable CTE
  identities across warm tracker, list and count compilation. Preserve nested
  scope, PostgreSQL materialization and every ACL/source predicate; removing an
  unused response read alone does not fix its shared query.
- Notification receipts must expose known UTC persistence timestamps with an
  explicit offset on both SQLite and PostgreSQL. Regress alert-day arithmetic
  before and after local midnight, including a non-UTC client timezone. Do not
  relax offset validation or reinterpret date-only legal inputs as UTC instants.
- Cross-dialect report acceptance must use populated canonical API responses,
  not only empty pages or simplified frontend fixtures. SQLite can return naive
  datetimes from UTC persistence; normalize known UTC fields at the response
  boundary without relaxing offset-aware frontend validation. Prove every
  report type, persisted dates and visible amounts after reload on both dialects.
- A fresh one-use setup or reset link can navigate within the same browser
  pathname without remounting React. Consume and scrub that new fragment,
  discard the previous form and fence stale responses. A forced page reload in
  the regression would hide the original failure.
- Replaying an invitation must not send another email, rotate its token or
  reactivate a revoked grant. Retain the original delivery's actual state,
  including failed or unknown sends. Only an explicit, bounded pending-link
  resend may issue a replacement; prove overlapping requests on PostgreSQL.
- A financial display regression must compare independent literal amounts,
  including sub-rupee costs, rather than reuse the formatter under test. Retain
  paise in recorded reports and provider unit warnings; rounding a positive
  charge to zero is not an acceptable dashboard simplification.
- An invalid MFA factor is not proof that its verification session was revoked.
  Exercise the real API client with its session provider, not only a mocked
  verification method. Preserve explicit retry only for the exact typed factor
  refusal; expired, revoked, malformed and unrelated 401 responses still clear
  access. Never reflect error-body secrets or retry verification automatically.

- Session-revocation acceptance must isolate the credential being probed. A
  password-reset response can set a fresh cookie that correctly takes priority
  over a stale Bearer header. Prove that precedence control, clear the cookie,
  then reject every retained tenant token and report session independently;
  preserve the original failed evidence rather than changing auth precedence.
- Cross-account reports must reconcile every persisted account category across
  source selection, segment construction, totals, HTML and plain text. A test
  with only law-firm and corporate fixtures cannot prove solo-lawyer coverage.
  Inactivity is evidenced human engagement over an explicit rolling window,
  not an account enablement flag, a completed calendar month, a polling audit
  or an arbitrary update timestamp. Collapsing a group must not remove its
  accounts or metrics, and email-client limitations remain explicit.
- Delegated operational reporting is not founder authority or tenant access.
  Keep its principal, token realm, cookies, MFA and live revocation fence
  explicit; never fabricate a tenant membership or widen founder-only billing
  mutations to make an admin dashboard convenient. Invitation/reset acceptance
  and report reads need negative cross-realm and stale-grant regressions.
- Public validation errors must retain field locations and actionable messages,
  never submitted input objects or validator contexts. Passwords and one-use
  tokens can otherwise be reflected in a nested 422 response. Prove this at
  the shared HTTP handler, not only in a form's error presentation.

- Before starting an expensive replacement release gate, read the latest
  source-bound CI failure handoff and current required-check state. A known
  failed security gate is not an in-progress gate. Preserve and supersede the
  old run safely instead of spending hours testing an already rejected lock.
  For dependency remediation, audit the entire resolved lock and the actual
  platform-installed inventory; a Windows freeze cannot certify Linux CI.
  Keep existing exceptions unchanged and prove native SDK compatibility plus
  the upstream failure boundary, not only a version string or a mocked client.

- A query-shape change requires an audit of every adjacent SQL observer, not
  only the changed query's tests. SELECT-prefix filters can reject or omit
  legitimate typed WITH reads, but WITH is not inherently read-only. Reuse the
  structural AST guard, reject nested DML and opaque TextClause/TextualSelect,
  retain every actual SQL event and charge all-statement budgets without
  ignoring CTEs or raising caps. Reconcile every failed case and all
  setup/call/teardown phases, not only the first failure or a green prefix.

- Alternating grants by insertion order do not bound UUID-ordered pagination.
  Regress known sorted record/docket identities and adversarial continuation
  pages, retain every actual plan, and keep total-work limits unchanged. Share
  canonical actor/tenant active-team SQL once per statement, never across
  requests. Prove actor composition and reauthorization after another committed
  grant, wall, team or membership change using the same prebuilt statement.
  Earlier random-fixture green cannot erase a source-identical later failure.
  Parametrizing a reused test also changes its direct wrapper contract;
  inventory those callers and execute every intended layout explicitly.

- Import validation errors and non-blocking source notes are separate facts.
  Pin the serving revision and saved original rows before diagnosing historical
  missing context. Revalidate retained originals after legitimate configuration
  changes without overwriting explicit source values or weakening expiry,
  draft/image and ambiguity fences. Valid rows and duplicate-skipped rows are
  not created records; read-only production diagnosis is not commit acceptance.
  Retained source notes must not claim the lifecycle or current date of a linked
  existing record; upload valid-row counts must never promise new records.
  Preserve legitimate multi-jurisdiction settings and require missing per-row
  context. Before/after query equality must match the known fixture identity;
  independently reread every created sibling after a duplicate-only import.

- Current workflow acceptance and an unidentified historical incident are
  separate claims. Reconcile each row against the complete exact-serving
  journey before retaining a stale unexecuted qualifier. An unrelated global
  release failure does not erase a passed row-specific result, and individual
  passes do not make the full release green. Preserve both scopes and history.

- Hash-pinned contract files must retain their canonical bytes across checkout
  platforms. Pin their Git line endings and prove the exact stored hashes;
  never accept a platform-normalized digest or rewrite reviewed fingerprints
  to hide checkout conversion. Preserve the failed run and replay its complete
  inventory after restoring only unchanged canonical document bytes.

- A correlated LIMIT does not bound inspected rows when policy filters can
  choose a broad tenant index. Seek one ordered primary-key candidate first,
  then require its exact identity, tenant and complete current policy outside
  that barrier. Retain full default/stale plans and unchanged work budgets.
  ClauseAdapter does not adapt a bare ORM Boolean attribute as a root clause:
  use explicit Boolean expressions and prove no unrelated base-table FROM
  remains. Regress wrong successors, walls, grant revocation and closed reads.

- Keep SQL DML construction and other potentially effectful calls outside an
  assertion, even in a compile-only negative oracle. Assert the captured result
  instead. Do not dismiss a required scanner finding because the current test
  never executes that statement; preserve that no-I/O distinction and rerun the
  required scan on the corrected source without suppressing the rule.

- A frozen historical-worker migration test must install its exact historical
  fence while that worker is paused, then release/join the worker and prove the
  complete captured current-head upgrade preserves the retained raw rows.
  Unrelated later concurrent-index builds must not run behind that deliberately
  held snapshot. Preserve the negative baseline, exact rejection SQLSTATE and
  migration lock budgets; pinning the fence alone cannot replace current-head
  coverage. Validate the compiled governance projection before Docker build,
  not just the human-readable map or an agent's manual checklist.
- An environment-driven negative control must verify the actual flag at the
  final pytest child, not only the controller environment. A green control
  that still installed the guarded schema is invalid counterfactual evidence.
  Retain it, correct only the transport and require the intended failure plus
  its actual schema boundary and raw effects in a fresh isolated database.

- One SQL statement is not a bounded-work proof. A correlated latest-row
  lookup can repeat a broad index scan per source under another valid plan.
  Pass the trusted tenant explicitly, filter it before ranking, reduce latest
  rows before materialization and charge removed rows, loops and history-sized
  CTE/intermediate work. Regress ordinary/adverse plans plus foreign same-ID
  histories without raising the original bounds or changing production planner
  settings. A local focused pass cannot waive a full-suite plan failure.

- History-work observers must attribute Bitmap Index Scan children to their
  owning Job relation even without a Relation Name, and charge loop-weighted
  intermediate/CTE work. Reject opaque TextualSelect/TextClause wrappers in a
  read-only AST guard, including nested DML, while positively testing the real
  typed materialized SELECT. Preserve the earlier undercounted green as scoped
  evidence, not proof of the corrected work bound.
- An index declaration is not proof of a bounded query plan. Capture complete
  default and adverse plans with the index created both before and after fixture
  seeding. A wider ordered index may lose to broad bitmap scans; accept only the
  measured tenant-scoped path without statistics, planner or deadline waivers.

- Windows acceptance must use a fresh short owned temporary root, separate from
  the longer retained-report path. Verify realistic nested document paths before
  launch and retain/copy sidecars durably. A long --basetemp that fails mkdir
  before attachment admission is failed setup, not a reproduced product defect;
  preserve its complete report and rerun the entire intended inventory.
- A missing concurrency barrier must surface a completed request Future's
  exception before reporting the barrier timeout. ThreadPoolExecutor teardown
  waits but does not propagate stored exceptions. Keep the original timeout,
  finally-release and normal result checks, with deterministic early-failure,
  completed-without-barrier, pending and reached-barrier regressions. Never infer
  an unobserved exception from sibling failures.

- A parameterized fixture still needs an explicit supported-input domain.
  Reject unsupported targets before admission and assign response-derived IDs
  inside the branch that creates that response. A green exercised subset does
  not clear a static uninitialized-variable finding; preserve the failed
  candidate and rerun fresh complete gates without scanner suppression.

- A reviewed origin fingerprint may recur at a historical merge or shifted
  line. Translate only after the reported immutable commit is in the selected
  history and the complete byte-identical span has one contiguous reviewed
  blame origin. Equal hashes alone, mixed origins and unknown provenance never
  authorize an exception. Retain the initial native failure and rescan the same
  full history; reconcile empty-diff commits separately from scanner counters.

- Calendar cancellation tests must follow the actual transport boundary. Matter
  cancellation commits exact `DELETE_PENDING` tombstones; drain the existing
  bounded worker before asserting provider DELETE, then prove retained
  sync/source/connection identity and second-drain idempotence. Shared IP hearing
  cancellation currently drains after commit; preserve that separate contract
  and never move provider I/O into the lifecycle transaction to satisfy a test.

- A bounded PostgreSQL lock observer must check its final existing snapshot
  before declaring a directed edge absent. A GC pause can exhaust the polling
  window while the required lock is present. Keep the exact waiter/holder PID
  assertion and snapshot-work bound; regress deadline-edge positives and wrong
  or absent edges without raising the timeout, then replay the real native race.

- Calendar renewal may advance a claimed credential snapshot only for its own
  rotation or a proven same-consent peer rotation. A new consent needs a distinct
  server-owned encrypted epoch even for the same account at the same timestamp.
  Capture immutable receipts under lock before commit; no ORM reload may reopen
  a transaction before provider I/O. Prove both interleavings on PostgreSQL.

- Signed search continuations must normalize queries exactly like the SQL
  predicate. Unicode case-folding is not interchangeable with lower-casing;
  regress distinct search inventories and reject cross-search cursor reuse.
- Saved recipient labels must resolve from a cold authorized directory even
  for a read-only viewer with no other mounted directory consumer. A prefilled
  query cache cannot prove the workflow; cover cold, cached, failed/retry and
  inactive/missing recipients without rewriting retained assignments.
- An expired refresh claim is not proof that the provider did not rotate its
  token. Preserve encrypted uncertainty after failed/stale receipts and lease
  expiry for revoked cleanup as well as connected grants. Repeated cleanup
  must not replay that token POST; new consent may replace the credential.
- Shared Calendar credential preflight must retain each caller's failure
  containment. Corrupt tokens and rejected refreshes must leave an unreadable
  connection unknown while healthy connections continue; an errored grant may
  authorize no provider read or positive match. Inventory drift, readiness,
  deletion, manual/bulk sync and reconciliation before the full Docker freeze.

- A Calendar status-load or schema-validation error is not evidence of missing
  OAuth configuration. Reconcile the actual tenant-scoped API response with
  every response enum, including retained `delete_pending` cleanup rows, and
  show explicit loading/error/unknown states. Never delete cleanup evidence,
  relax validation to arbitrary strings or fabricate missing credential names
  to make readiness appear coherent.

- A response enum's `verified` literal is not an implemented verification
  workflow or positive source proof. Trace the actual authoritative reader and
  writer before documenting or testing it. Do not promote supplied portfolio
  dates from a linked document, a manual correction or an unrelated confirmed
  deadline without the supported source-specific verification contract.

- Surface the first failed required CI gate immediately, with its actual
  artifact and any still-pending inventory. Do not leave an early-failure file
  unnoticed while waiting for unrelated jobs. Preserve the failed commit and
  results before replacing an owned, unmerged candidate. Describe public image
  checksums as typed immutable references, run the pinned offline secret gate
  before republishing, and never suppress a scanner finding to clear a release.

- GitHub may append a one-value matrix to a literal job name. Private-resume
  evidence must match one reviewed role/name form, require completed success
  and unique positive integer job IDs, and reject duplicate roles even when
  an alias failed. Use matrix-derived display names and regress captured API
  payloads, not only names synthesized from the workflow's intended roles.

- A valid Cloud Run job template is not executable worker proof. Exercise the
  immutable image's real console commands with cloud environment strings, not
  integer assignments on mocked Settings. Parse only documented protocol 0/1
  values, reject Boolean/float/unknown lookalikes, and prove both document and
  court disabled-admission startup offline before release. Keep active-work and

## Permanent regression learnings

- Native authorization can require fresh browser-session MFA even when ordinary
  tenant login policy is optional. Exercise that exact combination through the
  real system browser; a working server refusal without an inline verification
  path is not a usable sign-in. Keep the typed refusal, same-browser proof,
  principal recheck and explicit post-verification Connect; never auto-grant or
  turn off MFA to make the native journey pass.
- A privacy foreground flag that only updates a ref cannot redraw a signed-out
  app after background. Test actual Home/return with no credential or identity
  update, require the usable sign-in panel, and prove no automatic auth request.

- A native system picker can background and unmount private screens. Preserve
  only opaque tenant/user/membership/login/parent identity and the originally
  observed lifecycle version at the root; revalidate on return, require an
  explicit upload, and reject that original version under the server lock both
  before and after I/O. Never retain a hidden Matter DTO or adopt a reopened
  parent's new version to make an old selection succeed.
- A private native reader needs a genuinely streaming, bounded transport, not
  an unbounded global fetch followed by a size check. Bind exact download paths,
  source hashes, no-store, deadline/abort and login generation; purge visible
  content before renewing access. Unit/desktop rendering is not native cache,
  capture or revocation proof.
- Test screenshots and raw reports must remain outside the app's build input
  inventory. A passing renderer test that writes into its own source directory
  can dirty or change a frozen candidate; retain unique external evidence and
  compare the actual input fingerprint before and after the native build.

- Request-based Cloud Run does not guarantee CPU after the HTTP response.
  Public enquiry admission and founder retries must only persist the outbox;
  the scheduled worker owns mail claims and transport. Prove zero HTTP worker
  invocation, pending/zero-attempt replay and explicit worker delivery. Keep
  unknown-outcome no-resend and no-paid fences; do not increase billing to
  compensate for post-response delivery or call a queued response inbox proof.

- An atomic document-worker commit does not make a DTO assembled by separate
  READ COMMITTED statements coherent. Read source processing fields and the
  latest receipt together, include OCR policy inputs, and reuse the matching
  frozen IP version receipt. Prove initial-index interleavings through real
  PostgreSQL HTTP before claiming a fix; a delayed assertion or browser retry
  hides the defect. Preserve unrelated dirty state and fail closed on conflicts.
- Redacted production errors need distinct field-level assertion locations.
  Keep the original unknown tuple member unknown; later correct retained data
  does not reconstruct its HTTP response. A company-owned admitted worker may
  retain inactive-actor provenance while interactive access stays denied; new
  negative tests must respect that contract and pre-claim lifecycle neutralization.
- Completion-only agent waits do not deliver intermediate failed-shard status.
  Observe retained job-status checkpoints during a long verification, report the
  first real failure promptly, then reconcile every sibling and the complete
  replacement inventory. Never upgrade a release from its passing dated subset.

- Shared UI filters require route-to-service contract parity on every view,
  including grouped families and export; accepting an unknown query silently
  is not evidence that it was applied. Prove exact identities and continuation,
  reject changed cursor scope, and encode the database's actual sort key rather
  than a different Python Unicode normalization.
- Paging correctness on a small fixture does not prove interactive tracker
  performance on a retained tenant. Seed observed current-record volume plus
  valid provenance history, measure actual PostgreSQL plans, work and runtime,
  and bound compiled predicate expansion as well as query count. Keep exact
  category counts, current access/source checks and complete continuation; a
  longer timeout, approximate count or disabled safety predicate is not a fix.
- A successful unchanged production replay cannot explain an earlier failed
  journey. Retain the original complete result, distinguish loading/error/data
  evidence, and collect bounded sanitized primitives at the failing boundary.
  Diagnostic replays do not replace the complete exact-release certification
  or authorize private-maintenance resume from a failed QA run.

- A short directed-lock oracle must begin at the observed exact participant SQL
  admission, not an upstream worker callback that still has bounded preflight
  work to perform. Keep a separate bounded admission handshake, prove a delayed
  preflight cannot supply the edge, then require the real backend blocker, free
  parent and normal worker completion under the unchanged observation and SQL
  limits. Retain process-wide timing without inventing thread/object attribution;
  do not change production GC policy or raise a deadline to hide a missed probe.

- A strengthened dated browser setup helper changes its offline fixture contract
  too. Replay every consumer after adding required readiness metadata or return
  fields, assert the actual configured value on local and production-read-only
  paths, and reject malformed metadata without mutation. Do not invent a default
  timezone to make a simplified mock pass. Focused page tests cannot certify an
  omitted fixture module or replace complete frontend coverage.

  parent admission join. Retain the actual PostgreSQL plan under representative
  tenant volume and stale estimates, charge executor rows and loops, and avoid
  materializing the full authorized parent set before pagination. Preserve every
  access/lifecycle predicate and the original timeout. A first-page alternating-
  visibility fixture does not certify arbitrary sparse grants or later cursors.

- A new subscription/audit operator must run the existing canonical audit-owner
  coverage as well as its own complete unit/native modules. Use the shared
  audit writer with atomic caller-owned commit, deterministic replay identity
  and exact minimized receipt metadata. New-module-only green is incomplete.

  transport. Before native pytest, use the actual candidate-owned interpreter
  for a bounded host connection and SQL query. Retain failed setup as failed
  infrastructure, prove the fresh migrated template and rerun the whole unchanged

  deadline ties unchanged. Compare the actual old aggregation contract, keep
  new tie-break fields hearing-only, and preserve the complete dated calendar

  require one actual delivered attempt and visible reload, then clear the source
