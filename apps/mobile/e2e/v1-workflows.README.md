## Fixed four-stage fixture envelope

produces NONFINAL data. It also creates the separate synthetic company owner by
normal bootstrap/MFA APIs, preserving that private setup file before the first
POST and saving enrollment to the same inode before verification. Viewer creation
uses that actual owner acknowledgement, not a future or invented credential.

The four ordered, exclusively claimed stages are:

| Stage | Production HTTP | POST | Shared stage deadline |
| --- | ---: | ---: | ---: |
| Base | at most 96 | at most 64 | 180 s |
| Viewer | exactly 10 | exactly 7 | 60 s |
| Inbox | exactly 4 | exactly 1 | 90 s |
| Read-through | exactly 54 | exactly 49 | 180 s |

Each stage additionally charges exactly seven admission HTTP calls: API and web
identity before and after, normal actor login, MFA and current identity. That
adds 28 HTTP / 8 POST. The complete run is at most 192 HTTP / 129 POST under
one 510-second clock. There are no free serving, authentication or post-phase
reads. Stage claims and each HTTP key are consumed before effects. An unknown or
failed stage cannot be resumed, replaced or replayed. Final admission rereads all
four original hash-bound plans and receipts and their exact counters.
