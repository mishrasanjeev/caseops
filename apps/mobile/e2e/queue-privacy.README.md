# Separate queue and account-request native supplement

This is an executable two-case inventory (`QUEUE-01`, `PRIVACY-01`), six phases
and two distinct native sessions per platform. It does not modify core23,
Files17 or the Source/Work/Counsel/Inbox17 inventory, and cannot certify those
inventories, tablets, distribution, deletion fulfillment or complete V1.
No live fixture or native case has run from this source.

`node scripts/mobile/run-queue-privacy.mjs android|ios --collect` collects both
cases. `--request <absolute-json> <sha256>` requires the explicit
`CASEOPS_NATIVE_QUEUE_PRIVACY_GO=FINAL_SOURCE_MATCHING_WINDOW_RELEASED` window.
The persistent exclusive request claim is never removed after refusal or an
unknown outcome. The runner does not install, retry or filter cases. The exact
artifact must be installed once before actual source/build/signature/device/API
and web admission; both member proofs and each private reader are bound to that
same identity. The existing16KiB+1 reader closes and erases its verified buffer;
browser credentials are scoped/restored and never injected as native tokens.

`prepare-queue-privacy-fixture.mjs --pending` emits only pending requests,
producer and registration. `--from-producer <request> <sha256> <new-output>` is
a public projection of actual normal-API receipts. It never repeats creation
or authentication. Normal source-owned fixture actors precede this producer:
the owner, fresh member and separate-company viewer/owner come from canonical
bootstrap/extension/viewer APIs, with their retained private and actual MFA
receipts. The new producer creates two extra non-login peers privately before
their first normal user POST. Their passwords never enter public plans/events.

`produceQueuePrivacy` is the finite normal-API producer, using the same explicit
admitted owner-transport interface as `produceV1Dataset`. Its callbacks must be
bound in the live code closure; a test double is not an actual API adapter.
The before admission owns API+web reads and the four normal login/MFA pairs
(10 charged calls); after admission owns two final identity reads. All actors'
credentials must be admitted against current source/artifact/device/API+web
before their normal login. The normal isolated route-admission owner must admit
only actual acknowledged IDs; no wildcard, direct DB or paid/provider path is
accepted. Missing adapters or proofs refuse rather than manufacture receipts.

An uncertain response consumes its key and stops; failed setup files survive.

The disabled-default gateway profile is selected only by the literal
`CASEOPS_MOBILE_V1_PROFILE=queue-privacy-v1`. The default old profile and its
17-case/264-operation limits remain unchanged. The loader reads, hashes and
executes the new profile bytes and the exact pinned corrected helper bytes through
held descriptors. It never ordinary-imports a hyphenated module. Only existing
bounded reader/journal/normal `RegisteredOwner` HTTP helpers are reused. The
new profile allows no owner account mutation. Actor and authority references
include the owner UID retained from the verified descriptor. The shared17-case
validator/producer/client now use that same exact UID contract; the original
contradictory two-field candidate and its failed composition controls remain
retained. The original17 case identities and limits are unchanged.
It admits only exact new queue/account paths plus one known workspace and two
immutable owner anchor recipes. No registration means no enabled controls.

PRIVACY-01 cancels a confirmation without a POST, then sends one native
`{operation_id, confirmation:'request_account_deletion'}` POST. Before forward,
the gateway independently reads the native principal and requires the registered
global User, membership and company. It consumes one claim, retains the original
upstream202 exact receipt, then drops only that client acknowledgement. The UI
must remain Unknown. One explicit receipt read follows observed Unknown; there
is no20-poll expansion. An explicit GET reload settles the same receipt and a
new Account visit confirms read-only persistence. Reloads bind new completed
native GETs, with at most four finite reads under each original20s deadline.
Another normally authenticated user sees its own null result. Final logout
clears receipt/queue detail and each owned session must close.

The new run has an8min ceiling and keeps existing10s read/20s transition/60s
transport/200ms polling bounds. The literal worst-case control table is18 Queue
RPCs +17 Privacy RPCs +one final cleanup =36 within the separate49 ceiling
(24 per case +one final cleanup). This includes all receipt/request polls and
case cleanup. The new gateway additionally charges every actual helper HTTP

The colocated Node module exercises real producer/decoder/admission/client
functions with synthetic FS/HTTP doubles; the Python profile tests exercise the
actual held-source loader and202 protocol without network. The independent
Python module fixes the exact2/6/2 counts and old-inventory separation. CI/LF,

Future actual final-source/API/native evidence and independent review are still
required before enabling the descriptor or declaring either case passed.

Private actor and control-authority references are exactly `{path, sha256, uid}`.
The UID is retained from the opened, verified descriptor by the private writer
and is checked again before bytes are used. Missing, Boolean, negative or
unmatched UID metadata refuses; no process-UID fallback is permitted. POSIX
owner/mode controls do not certify Windows ACLs. Existing pending references
remain null until the actual descriptor evidence exists.

The control journal fsyncs the fixed native202 receipt before it permits client
response loss. A failed journal retains the consumed claim and unknown outcome
and never permits intentional loss or automatic replay. Final control completion
is written before the real journal closes. The gateway rejects cookie authority
(including an empty Cookie header), missing authority and web bearer authority
for the newly admitted privacy POST before any upstream request.
