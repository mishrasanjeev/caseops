# Native privacy disclosure draft

This review covers photo uploads, the optional biometric screen lock and workspace conduct reports at CaseOps revision `013b9a3c`. Apply these rows to the rest of the app’s existing data inventory when completing each store form. The [public policy source](../../apps/web/lib/privacy-policy.ts) keeps its current effective date in this draft. Assign the amended policy its actual effective date and version at publication, then reconcile the owner-approved policy reference used in each store build. See [privacy policy configuration](PRIVACY_POLICY_CONFIGURATION.md).

| Data and handling | Google Play Data safety | App Store Connect App Privacy |
| --- | --- | --- |
| Uploaded photo, original file and associated file information. Taking or picking an image is separate from uploading it. CaseOps retains the uploaded bytes under the signed-in workspace. | **Photos** and **Files and docs**. Collected, optional, retained, **App functionality**. Include **Coarse Location** if the release path also collects that type. |
| Optional biometric screen lock. The operating system authenticates access to a protected value and CaseOps keeps the lock settings in device storage. The authenticated account still follows the usual server checks. | Biometric templates and the local lock decision add no collection or sharing entry for this feature. Continue to account for server-side sign-in data under its existing types. | The local lock adds no **Sensitive Info** entry for biometric templates. Account authentication remains a separate disclosure. |
| Workspace conduct report. The server retains the reporter’s workspace membership, references to the source matter and item and, where applicable, the reported member, selected reason and receipt time. Intake returns limited report details to authorized reviewers. | **Other user-generated content** for the report, collected, optional, retained. **User IDs** for the membership references, with required status determined across the app’s existing sign-in flows. Purposes **App functionality** and **Fraud prevention, security, and compliance**. Apply the sharing rule below. | **Other User Content** for the report and **User ID** for membership references. **App Functionality**, linked to the user, no tracking in this flow. |

Google’s sharing exceptions apply to processors acting on the developer’s instructions and to specific user-initiated transfers where the recipient is reasonably expected or an applicable disclosure and consent covers the transfer. Verify the actual basis for transfers to separate workspace organizations, including where a workspace owner receives report details. Mark each relevant type **shared** if a release recipient falls outside the exceptions. A customer’s choice to upload does not establish the exception for later provider processing. [Google Play Data safety guidance](https://support.google.com/googleplay/android-developer/answer/10787469)

Apple’s label includes retained data linked to an account even when the feature is optional. Treat these workspace uploads and reports as reportable. Check the published label against the final iOS app, backend, and partner practices. [Apple App Privacy Details](https://developer.apple.com/app-store/app-privacy-details/) · [App Store Connect privacy form](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy)

Source evidence for the [camera and upload path](../../apps/mobile/src/files/native.ts) and [camera behavior](CAMERA_CAPTURE_2026-10-27.md) distinguishes suppression of a separate metadata response from the image bytes themselves. Release verification should check effective permissions and compare an uploaded synthetic image with its readback. The [biometric store](../../apps/mobile/src/auth/biometric-store.ts) and [screen lock design](BIOMETRIC_SCREEN_LOCK_2026-10-27.md) describe the on-device boundary. The [report payload](../../apps/api/src/caseops_api/schemas/workspace_conduct.py) and [intake service](../../apps/api/src/caseops_api/services/workspace_conduct_reports.py) define the stored references and the two reviewer scopes.
