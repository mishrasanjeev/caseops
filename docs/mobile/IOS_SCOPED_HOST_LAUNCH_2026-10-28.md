# Scoped local iOS host launch

This is guarded preparation and a local launch contract. No native build,
production signature, store admission, download or owner account is certified by
its source tests. The default store recipe remains plan-only.

`ios-host-launch.mjs` prepares an immutable `caseops-ios-host-launch-v1` policy in
one new current-user 0700 directory. Its public inputs are a reviewed Node24
H/B policy, exact accepted executable references (Node24.15.0, Ruby4.0.9,
CocoaPods1.17.0, curl8.7.1, Python3.13.17 and the operator-bound Git, developer
Xcode binary and plutil), the canonical public Ruby188 bundle, an optional exact
Node-native-QA fixture CA, and an invocation deadline no later than one hour.
All references carry canonical path, SHA256 and byte length. Tool versions need
independent operator/readiness evidence; descriptor text does not prove them.
The OS `/usr/bin/xcodebuild` dispatcher has multiple hard links on this host and
is refused. Admit the independently bound single-link developer binary instead.

The policy binds its actual helper bytes, pinned Ruby constructor, retained
simulator body and unchanged Python worker/owner. Generated node/npm/ruby/pod/curl/git
shims execute a held, hashed helper buffer. The simulator entry likewise pins
and consumes the helper buffer; a public descriptor cannot authorize new code.
LF attributes preserve these byte contracts. `source-snapshot.mjs` includes the
new body and host inputs in the mobile build fingerprint.

The child recipes use separate stores. Node gets its exact five-field H/B
recipe (plus the one explicitly admitted QA fixture when applicable), Ruby gets
all188 reviewed Ruby roots, and curl gets a new explicit selected-file Curl188
role. Nothing here establishes curl's OS-native default trust. Ruby's public
Cellar default gem directory and the accepted Pods libexec are the only gem
paths. There is no owner `.gem`, profile, netrc or curl-config inheritance.
Each recipe has an owned HOME/CURL_HOME/XDG home, CP home/cache/repos and TMPDIR.
The generated `apps/mobile/ios/Pods` path is separately derived from the bound
source checkout; CP_HOME_DIR does not change CocoaPods' project Pods root. The
deferred generated root and every parent back to that checkout must be canonical,
current-owned and not shared-writable before downloads. This admits normal0755
generated parents without granting mutations throughout the checkout.
Node SSL variables are absent from Ruby, curl and neutral Xcode children;
Podfile backticks and NODE_BINARY both resolve the owned Node shim.
Only actual Node children receive four anonymous npm settings: immutable
EXCL0600 comment-only user/global configs, strictSSL true and the public npm
registry. Conflicting or lowercase npm overrides and project/home `.npmrc`
presence refuse without reading those files. Absence is checked at admission,
before Node dispatch and after completion; this remains a frozen-writer,
pointwise check. The owned npm shim binds Node24's npm11.12.1 package/short entry
and admits only `--version`; it never selects Homebrew npm or grants install,
login or publication. Canonical `prebuild --no-install` uses the installed
`expo/template.tgz`. Custom-template/monorepo npm operations are outside this
fixed build profile until separately reviewed.

CocoaPods' exact CLI curl form retains output, URL, headers, User-Agent and
retry2. The wrapper puts `--disable` first, fixes HTTPS-only redirects, admits
only that argument form and rejects abbreviations, later config/CA/proxy/bypass
options. It adds the exact verification marker when absent. CA bytes already
verified through one descriptor populate a fresh EXCL regular0600 copy, read
back on the same descriptor and made0400; that descriptor is passed as FD3.
Curl's CA pipe support was experimentally refused with exit77 and is not used.
The final descriptor/name/namespace and owned-home frames must still match
before deleting only that admitted copy. A replaced namespace is retained for
review, never removed by a broad prefix cleanup.

The separately pinned Ruby preload covers the actual Pods CDN Typhoeus/Ethon
constructor: explicit selected CA/capath, peer and hostname verification, exact
no-paid marker, preserved URL/ETag/gzip/http2/timeout10/connect10 and retries.
Contradictory TLS/proxy/netrc options refuse. It checks the owned CA and HOME
again afterward. Actual local positive, unknown-CA and wrong-host controls are
required independently for this runtime. Its selected-file API is qualified;
it is not a whole gem-library or Apple native trust claim. CocoaPods' `which`
normally prepends `./`; the reviewed constructor resolver fixes known tools to
the owned shims instead.

The installed React Native/Hermes archive, redirect, HEAD and SHA1-sidecar curl
forms have separate literal allowlists. Existing arguments and caching/checksum
semantics remain unchanged; missing upstream SHA1 is not promoted to a verified
archive. The Ruby Net::HTTP GET constructor uses the retained188-root in-memory
X509 store, peer/hostname checks and the exact marker, preserving its finite
default timeouts. Unknown CA and wrong host remain refusals.

Git admits only the actual public HTTPS ls-remote/clone forms and scoped owned
repository commands. It disables owner/global/system configuration and inherited
worktree discovery, fixes CAInfo/emptyCAPath, certificate checks, protocol,
credential-helper and marker settings, and rejects config includes, URL rewrites,
TLS overrides and external object stores. Mutations are confined to the new
invocation's cache/temp/Pods/repos namespaces; canonical ownership, config and
parent identity checks also run afterward. It preserves the upstream explicit
shallow fallback; it never adds an automatic retry after an unknown outcome.

Git parallel object fetch cannot safely reuse `/dev/fd/3`: the retained failed
clone returned128/curl77 after its first successful requests. Its separately
qualified selected-file role therefore points CAInfo at the unique EXCL0400
copy in an owned0700 namespace, while keeping the original descriptor and full
file/parent/canonical observations until final cleanup. This does not claim Git
consumed the producer FD or prove atomic/lifetime pathname immutability; writers
must remain frozen. Curl retains its actual descriptor transport. Local marked
positive/unknown-CA/wrong-host controls are independent for both APIs. None of
these roles certifies Git/curl OS-default trust, arbitrary downloaded scripts,
Swift/package resolution or the complete installed Ruby/native dependency tree.

`build-ios-simulator-acceptance.sh` requires the policy FILE/SHA256/SIZE, exact
`CASEOPS_IOS_HOST_NODE`, and
`CASEOPS_IOS_SIMULATOR_BUILD_GO=EXPLICIT_REVIEWED_LOCAL_SIMULATOR_BUILD`.
The retained body preserves Release/ad-hoc signing assertions, four Xcode jobs,
raw private build logs and final binary receipt. One exclusive claim precedes
its single owned local-QA Python host. Its body is at most1800 seconds plus the
existing30-second owner cleanup inside the policy deadline. This distinct typed
`public-local-qa-only` protocol admits the persistent cleanup parent before
dispatch, naturally waits through Git/Xcode exec/cwd churn without claiming a
live descendant inventory, then invokes unchanged strict eaa final cleanup and
current-group/recorded-identity absence. It is finite pointwise evidence, not
exhaustive lifetime/detached/exec-transition proof. Its request, source, stdout,
stderr and cleanup bounds retain the existing values. Store/signing continues
to use the unchanged live-sampling store host and remains separately unarmed.
The original submodule body0/strict-owner-false result is retained distinctly.
Neither role retries an unknown attempt or claims native inventory acceptance.

Store execution requires `tools.iosHostPolicy` (null on Android), binds its
actual Node/Ruby/Pods/curl/Python tools before reservation/signing, and composes
each command separately. Existing full source/security/native gates, monotonic
number reservations, signing boundary and artifact postflight remain required.
The explicitly admitted profile can be copied into the isolated home only at
the existing signing boundary; no current key/profile is read by preparation.

Source controls are contracts and POSIX filesystem controls. Actual Windows
native execution is unsupported; Windows exercises that refusal without a skip.
Original source, transport and preparation failures remain retained with their
own scopes. Runtime/import closure and full release gates must be replayed on
the eventual integrated candidate. No global CA/keychain/default environment,
production policy, account, upload or deployment is changed.

The Node inner recipe now carries a pinned names-only inventory from one actual
retained f91 React Native bundle phase: Xcode/SDK27.1 targeting Simulator27.0.
It admits586 bounded public build names and excludes owner, TLS, preload, proxy
and dynamic-loader fields. These are observed names, not retained values or
future native acceptance. The outer recipe still starts from its small public
input set; unknown future names refuse. Legitimate LD linker-setting names are
kept distinct from LD_PRELOAD and other loader overrides. Bash rejects dangerous
loader-family variables before starting Node; the Node recipe checks them again.
The unchanged strict process owner also needs its actual build-churn proof before
a native/store GO; a source-contract pass does not waive a convergence refusal.

Pure local Git inventory uses a separate retained, hash-pinned Python3.13.17
bootstrap instead of starting Node/TLS verification for every BFS directory. It
admits only `--version`, `rev-parse HEAD`, the exact fixed `ls-files`/`status`
forms with at most256 arguments, and `check-ignore -z --stdin` with at most1MiB
of byte-preserved stdin. The policy, source helper and actual Python/Git inputs
retain descriptor/namespace checks. The local source repository must be canonical
and owned; config includes, external object stores, owner global/system config,
credential helpers, hooks, fsmonitor, lazy fetch and all network protocols are
unavailable. Mutation/network Git still uses the existing selected188 role.
The original complete SourceSnapshot remains bounded by5seconds and retains its
failed slow-shim attempt; local Git transport is not TLS or native acceptance.
