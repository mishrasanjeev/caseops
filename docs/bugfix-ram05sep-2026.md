## Root Causes And Local Corrections

1. **BUG-010 remains Not fixed.** The deployed catalog contains 23 Acts and
   3,393 sections but only Article 14 is verified. All five Acts named in the
   report have zero verified sections. Previous positive fixture coverage and
   honest disabled-state copy did not make the broader catalog usable. This
   is incomplete source data, not a reason to remove the trust predicate.
   Several seed source handles and legacy section labels also need source-level
   reconciliation. No remembered/AI-generated text was promoted to official law.
2. **The template invited invalid assignments.** Source row 2 copied the
   example owner, lawyer and team. Those identities do not exist in the tenant.
   CSV and XLSX examples now leave optional assignments empty. Both original
   download formats round-trip in a fresh tenant without tester corrections.
   Other copied sample fields in source row 2 still require the uploader's
   factual review; CaseOps must not invent replacement client/case facts.
3. **Duplicate claiming happened before admission.** Invalid rows, and rows
   skipped for an existing identity, reserved their other identifiers despite
   creating nothing. Later valid rows were suppressed. Claims now occur only
   for admitted rows. Tests cover code, case number and title/client separately,
   duplicate chains, commit, replay and unchanged existing records. A legacy
   assertion that required the suppression bug was corrected.
4. **Court context was discarded on adjacent paths.** Explicit catalog-ID and
   category/name imports could replace conflicting supplied context with the
   catalog's lineage. Both now use the context predicate. Uncatalogued paths
   preserve supplied location without inventing a catalog ID. Manual explicit
   selection also rejects invented metadata where the catalog has no value.
   Regressions cover State, District, City and Consumer Level, plus the three
   supported uncatalogued input forms and preview/commit persistence.
5. **Temporary identity was missing across contracts.** Added a nullable
   120-character field, independent of Case Number, CNR and Filing Number,
   across database, API, workspace DTO, frontend validators, create/edit,
   search and bulk workflows. Final identifiers do not erase it. The migration
   builds four concurrent trigram indexes and refuses destructive downgrade
   once populated. Restart coverage deliberately creates a real invalid
   PostgreSQL index, repairs it, upgrades again and proves data retention.
6. **Qualified source labels were missing from the catalog.** A data-only,
   idempotent migration adds three aliases, without parser exceptions:
   `Tis Hazari (West)`, `Dwarka-Consumer Forum`, and `TDSAT- New Delhi`.
   Identity evidence is the official [Delhi court circular directory](https://delhidistrictcourts.nic.in/circulars),
   [Delhi consumer court directory](https://fsd.delhi.gov.in/fs/consumer-courts-delhi),
   and [TDSAT contact directory](https://tdsat.gov.in/writereaddata/Delhi/docs/contact_detail.php).
   Existing review/deactivation decisions survive reruns. Data-only rollback
   retains these records; the owning schema keeps its evidence-removal guard.
   This does not resolve unqualified Saket/Tis Hazari, city-only labels,
   private arbitrators, or every remaining source row.
7. **Commit revalidated its own output, not the user's evidence.** It rebuilt
   input from `normalized_json`, retaining a derived catalog ID even after the
   original alias was withdrawn. Both first confirmation and interrupted-job
   recovery now re-resolve `raw_json`. A changed previously resolved canonical
   court is rejected and requires a new preview, not a silent reassignment.
   Forced withdrawal and retargeting tests cover both paths.
8. **A successful billing save could disappear visually.** A fresh Docker
   trace captured POST 200 with a complete saved profile followed by an older
   list response with `profiles: []`. Saves now wait for initial discovery;
   exact stale list queries are cancelled before caching the returned server
   record and refetching. The sibling rate mutation follows the same boundary.
   Failed loads remain actionable and cannot be mistaken for an empty catalog.
   Four new unit cases and a dated held-request browser journey cover this.
9. **Billing edits could overwrite saved details.** The form displayed hardcoded
   defaults instead of hydrating the existing profile. It now waits for the
   authoritative profile, preserves dirty input during refetch and PATCHes only
   changed editable fields. New tenants no longer inherit a fabricated firm
   name. Tests prove an address change leaves GST applicability, billing mode,
   payment terms and invoice sequence untouched.
10. **The same stale-list pattern affected outside counsel.** A second real
    browser trace captured work-product POST 201 followed by the pre-upload
    GET's empty list. Work-product, invoice and time-entry mutations now cancel
    old exact list requests before awaiting a fresh list. All three unit and
    browser workflows force this ordering and assert visible persisted results.
