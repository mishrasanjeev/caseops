## Ownership and duplicate-work analysis

Classification: **EXTEND**. No new table, migration, or writer.

- Alerting calls the existing `enqueue_notification_delivery_intent`
  dispatcher. **No second notification owner was created.** The dispatcher's
  own idempotency key (derived from `source_type`/`source_id`) provides
  duplicate-send protection; the disable status guard is the primary control.
- `ip_rule_sets.rule_kind` already carried `deadline`/`form`/`fee` from
  `IPLF-023A`, and `propose_deadline` already rejected non-deadline kinds. This
  slice adds the missing **proof**, not a new mechanism.
- Recipients are resolved from existing `IpResponsibilityAssignment` rows; no
  parallel responsibility or escalation model was introduced.

No schema change, no migration, no backfill, no API surface change.

## Delivery safety

- Intents are **`in_app` only**. No email, SMS, or other external channel is
  used, and no external delivery is enabled by this slice.
- `confidentiality_mode="minimal"`: the alert body names the affected deadline
  title and the disable reason, not privileged legal content.
- Recipients are filtered to active memberships of the acting company;
  the dispatcher independently re-checks matter access per recipient.
- If a record has no assigned owner, the acting user is alerted so the
  suspension cannot be silently lost.

## Explicit caveats

- **Local SQLite only.** No real-PostgreSQL CI, no deployment, no production
  verification, no frontend surface, no E2E. `release_status` stays `blocked`.
- **Form rule kind is proved only through the fee path.** `form` shares the
  identical non-deadline fixture branch as `fee`, but has no dedicated test.
- The rule routes are still named `/deadline-rules` even though they accept
  `form` and `fee` kinds. The naming is misleading; a rule-kind-neutral route
  alias remains open work and is recorded on `IPLF-027B`.
- Alerting is proved at the service/persistence boundary by asserting the
  queued `NotificationDeliveryIntent` rows. **No delivery worker run, no
  in-app UI render, and no recipient-visible proof is included.**
- Fixtures are synthetic. No lawyer-approved fee schedule or legal rule text is
  attached, and no official fee amount in these tests is authoritative.
