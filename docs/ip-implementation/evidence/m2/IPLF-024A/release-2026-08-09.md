## Delivered scope

1. `ip_document_taxonomy_entries` and `ip_document_taxonomy_aliases` provide a
   tenant-owned, versioned, auditable taxonomy with normalized aliases.
2. `ip_documents` owns stable IP document identity independently of a synthetic
   Matter.
3. `ip_document_versions` owns immutable filename, storage-key, digest,
   processing evidence, OCR/extraction evidence, state, and approval locks.
4. `ip_document_links` binds a document, and optionally one of its versions, to
   exactly one docket, application, proceeding, event, or deadline.
5. Company-scoped composite foreign keys fail closed for taxonomy, actors,
   document/version relationships, and every typed legal-record target.
6. The existing shared document store and `document_processing_jobs` remain the
   only binary and processing owners. `ip_document_version` is reserved as the
   typed processing target for IPLF-024B; this slice creates no second queue.
7. The read-only naming preview normalizes Unicode, strips unsafe/reserved
   filesystem content, protects spreadsheet exports, caps names at 240
   characters, and resolves collisions deterministically.
8. Taxonomy seeding is explicit and idempotent. Reads do not create data;
   writes require `ip:taxonomy_admin`, optimistic concurrency, normalized alias
   collision checks, and audit events.
9. Approved/filed version states require an actor and timestamp. Invalid target
   totals/type pairs, cross-document versions, invalid hashes, sizes, OCR
   scores, and states are rejected by database constraints.
10. Migration `20260809_0001_ip_document_foundation.py` is additive from
    `20260807_0005`; no legacy MatterAttachment data is copied or rewritten.
