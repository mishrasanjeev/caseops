## Defects found and fixed in existing IPLF-023B behaviour

1. **Silent retirement of a still-effective rule version.** `activate_rule_version`
   retired *every* other active version of a rule set regardless of effective
   range. Activating a 2027 rule silently retired a still-in-force 2026 rule.
   Retirement is now limited to versions whose effective range actually collides,
   and collision requires an explicit `supersede_overlapping` acknowledgement.
2. **Impact preview understated activation impact.** `rule_impact` counted only
   records attached to the version being previewed. For a candidate, the records
   at risk belong to the active version it will supersede, so the preview
   returned `0` for a change that would supersede a confirmed deadline. The
   preview for a `candidate` now spans the versions it would supersede.
3. **No stale-preview protection on activation.** `transition_rule_version`
   required a matching `impact_token`; `activate_rule_version` did not. Activation
   now requires the token whenever the change has impact (ARCH-OPS-05).
4. **Emergency disable did not stop auto-confirmation.** Disabling a rule set the
   version status only. Tenant policies kept `auto_confirm_eligible = true`, so a
   withdrawn rule would remain auto-confirmable once auto-confirm ships. Disable
   now clears the flag for every affected tenant policy and records the affected
   company IDs in the audit metadata.
