## Delivered contract

- Added all 13 canonical PRD Section 2.2 IP capabilities to the backend and
  frontend catalogues with the exact default role matrix.
- Preserved three bounded-tail legacy aliases so existing sessions and custom
  roles do not fail during mixed revisions.
- Published 11 typed feature definitions. Each separately names required
  capability, billing entitlement, safety flag, expiry setting, accountable
  owner, automation classification, and manual fallback.
- Added a pure fail-closed evaluator with stable reasons for missing
  capability, missing entitlement, disabled rollout, expired rollout, unknown
  feature, and available state.
- Added eight independent rollout flags and eight optional expiry settings.
  All flags default off; absent or elapsed approval never activates a feature.
- Documented every environment variable in `apps/api/.env.example` and the
  operator/security contract in `docs/ip-implementation/IP_CAPABILITY_MODEL.md`.

## Security and architecture assertions

- Server capability, billing entitlement, and safety rollout are evaluated as
  independent inputs in accordance with ARCH-OPS-12.
- Frontend `can(...)` controls presentation only and is never accepted by the
  backend as authorization proof.
- Missing provider readiness disables only the dependent automation; manual
  docketing remains a declared fallback.
- Unknown features and ambiguous entitlement values fail closed.
- No duplicate entitlement store, membership owner, feature-flag database, or
  IP-specific authorization engine was added. Existing membership, billing,
  settings, and frontend capability owners are extended.
- There is no schema migration, backfill, tenant mutation, provider call,
  notification, legal message, filing, or fee effect in this slice.
