## Data safety and authorization

All new rows are tenant-scoped and use composite foreign keys to tenant-owned
parents. Core record reads/writes use the docket access and lifecycle guard;
workspace administration requires `ip:taxonomy_admin`; legal record reads and
writes require `ip:read` and `ip:write`. Audit metadata does not copy raw legal
identifier values.

Workspace persistence stores only provider references and accepted terms, not
credentials. It does not send notifications or contact providers. Capability,
billing entitlement, deployment rollout, and tenant allowlisting remain
independent fail-closed decisions.

## Rollout and rollback

The production migration is additive. It creates empty configuration/test
tables and performs no backfill or legal-state inference. No production IP
rollout environment flag is enabled by this candidate.

Before any production activation, the exact merged commit must pass independent
CI/Security/CodeQL and PostgreSQL migration checks, be deployed from canonical
`main`, and have its exact API/web digests and Cloud Run revisions verified.
The same dated Playwright path must then pass against that serving revision.

Before writes, `20260807_0002 -> 20260807_0001` downgrade is tested. After
writes, rollback is tenant/environment flag-off plus forward fix and
export-preserving recovery; destructive deletion of legal/configuration history
is not authorized.

There is no arbitrary seven-consecutive-day scheduler-health gate. Scheduler
health is verified deterministically for the exact production release where
applicable, while genuine named human and provider approvals remain pending.
