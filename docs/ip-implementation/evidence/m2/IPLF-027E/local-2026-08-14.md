**Milestone:** M2

## Scope

`IPLF-027A` already supplied the **mechanism** for mixed-revision safety:
immutable outbox envelopes with `producer_revision`, leases, fence versions,
per-consumer effects, dead-letter handling, and a downgrade that refuses to
delete evidence. What was missing was **journey-level proof** of UJ-67's stated
acceptance:

> Old and new revisions coexist without corrupting legal state, and rollback
> after a committed event preserves that event and prevents duplicate consumers.

This slice supplies that proof for three of seven UJ-67 paths. It adds **no
production code** — it is test and evidence only.

| Path | Status | Note |
|---|---|---|
| `UJ-67-NORMAL` | **implemented** | Old and new producer revisions write the expanded schema concurrently with distinct immutable identities; a new-revision worker drains the old revision's event through the full consumer set without touching the other. |
| `UJ-67-EXC-02` | **implemented** | Unadmitted schema version, unadmitted event type, and a payload missing a required contract field are each rejected; no partial row survives and the admitted event is unaffected. |
| `UJ-67-EXC-05` | **implemented** | Runtime controls are fail-closed by default; a post-rollback worker generation cannot re-claim a succeeded event, and exactly one effect row per consumer remains. |
| `UJ-67-EXC-01` | **open** | Lock/table-scan window needs real PostgreSQL lock timing. |
| `UJ-67-EXC-03` | **open** | No backfill owner exists in this slice; data operations belong to `IPLF-028` and are blocked on approved policy. |
| `UJ-67-EXC-04` | **open** | Canary/SLO failure needs a real deployment. |
| `UJ-67-EXC-06` | **open** | Only the destructive-downgrade *refusal* half is covered, by the existing `test_20260812_ip_workflow_lifecycle_migration.py`. The restore/roll-forward rehearsal needs an authorized SRE run and overlaps the `IPLF-028A-RES-13-REHEARSAL` blocker. |

## Explicit caveats

- **SQLite only.** The outbox uses `SKIP LOCKED` on PostgreSQL and a
  serialization shim on SQLite, so the concurrency characteristics proved here
  are **not** the production ones. Real-PostgreSQL CI remains required.
- **"Mixed revision" is simulated at the data boundary**, by two distinct
  `producer_revision` values writing the same expanded schema in one process.
  It is **not** two application processes at different code revisions, and it
  is not a deployment. A true mixed-revision rollout test needs CI or staging.
- **"Rollback" is simulated** as a later worker generation re-claiming after the
  lease window, plus the fail-closed default flags. No Alembic downgrade, no
  image rollback, and no traffic shift is exercised here.
- No delivery worker, no canary, no SLO observation, and no restore rehearsal.
- `ARCH-OPS-10` remains `in_progress`; this slice does not close it.
