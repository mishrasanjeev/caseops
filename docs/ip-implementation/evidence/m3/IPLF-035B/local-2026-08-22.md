## Existing-owner audit

The implementation was reassessed against current `main` before editing.
IPLF-007C already owns durable notification intents, retries, suppression,
fallbacks, webhooks, recovery and admin visibility. IPLF-023B and IPLF-025B
already own legal dates, shared hearings, next-hearing history, reminders and
calendar projections. IPLF-034B owns the governed legal-deadline workspace, and
IPLF-039C owns external-calendar projection and drift review.

Accordingly, IPLF-035B creates no table, migration, dispatcher, provider
adapter, IP-private hearing/reminder/calendar owner, or suggestion history. It
extends the existing shared response and user workflow only.

## Implemented delta

- An unpublished hearing time now exposes
  `time_confirmation_required=true`; no default time is manufactured.
- The IP workspace keeps date-based reminders visible and offers an empty
  published-time input. The user must enter the time before confirmation.
- Confirmation uses the existing locked shared-hearing update writer. Its
  existing scheduling transaction cancels pending reminders/intents and
  creates the next generation.
- Reminder rows expose `is_superseded` and their immediate
  `replacement_generation`; the hearing exposes a live
  `current_schedule_generation` only while a non-cancelled generation exists.
- A fully cancelled hearing therefore has no false current generation, while
  its historical immediate replacement links remain inspectable.
- The web surface shows every generation instead of filtering cancelled rows.
  At 360 px, the controls remain reachable and the page has no horizontal
  overflow.
- The user guide, law-firm page, API types and canonical calendar/reminder
  workflow document describe the same behavior.
