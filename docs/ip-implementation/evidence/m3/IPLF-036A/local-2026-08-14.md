## This slice writes no product code

Auditing `IPLF-036`'s scope found the document register, taxonomy, controlled
naming, versions, approval locks, duplicate detection, and privilege policy
**already fully implemented and tested** by `IPLF-024A/024B`. There was no
implementation gap to close.

What was missing was **traceability**: all five `UJ-14` paths still carried
`planned:` test references, so the manifest recorded no evidence for behaviour
that has been shipped and passing for days.

This slice maps the existing passing tests to the paths they actually prove.
**The credit for the implementation belongs to `IPLF-024A/024B`, not here.**

## A systemic finding, not just this slice

Counting across the whole manifest:

- **285 of 317** journey paths still carry `planned:` test references.
- **100 of those are `in_progress`**, meaning an owning slice has already
  landed — so a substantial amount of shipped, tested behaviour is recorded as
  unevidenced.
- **18 are already marked `implemented`** while still carrying a `planned:`
  reference, which is an internal inconsistency the validator currently
  tolerates.

The program's apparent remaining work is therefore **overstated**. Before
implementing any further M3 slice, the cheaper and more accurate move is to
audit each one against current code first — three consecutive slices
(`IPLF-031A`, `033A`, `034A`) turned out to be mostly built already, and
`IPLF-036` turned out to be entirely built.

**Recommendation:** treat "map existing passing tests to their paths" as its own
workstream. It converts no-code effort into accurate program status, and it
stops future slices re-implementing what exists.
