# IPLF-032B - shared import compatibility and activity workflow

**Slice:** `IPLF-032B` (M3; repository-implemented, locally verified, not released)
**Implementation revision:** `778fc3ba`

**Program status:** `PROGRAM INCOMPLETE`

## Allocation review

The audit found a narrow requirement still open after IPLF-032A and IPLF-030B.
IPLF-032A created neutral `bulk_import_jobs` and typed IP staging. IPLF-030B
already delivered the controlled trademark CSV/XLSX uploader, duplicate
reconciliation, history, retry/cancel behavior, responsive UI, and E2E proof.
Neither slice implemented the PRD Section 11.2 requirement for shared
status/manifest/error/download APIs and read-only adapters over the legacy
Matter and Employee job owners.

This slice closes only that gap. It does not duplicate the importer, add a
second uploader, replace Matter/Employee ownership, or reopen IPLF-030B.

## Delivered contract

- Added authenticated `/api/imports` history, summary, manifest, and normalized
  error-report routes for `ip_trademark`, `matter`, and `employee`.
- Preserved canonical source status while exposing one bounded lifecycle for
  cross-domain display.
- Preserved each owner's authorization boundary and returned indistinguishable
  `404` responses for unknown and foreign-tenant jobs.
- Declared the missing legacy employee checksum instead of manufacturing one.
- Added `/app/imports` with permission-aware domain filters, status/count rows,
  manifest review, error CSV download, and links to each canonical importer.
- Added the activity view to the app navigation and documented it in the user
  guide and `BULK_IMPORT_COMPATIBILITY.md`.
- Regenerated the OpenAPI TypeScript projection.
