## Reconciliation and root-cause findings

The earlier implementation rendered the correct report names but left four
repository-controlled correctness gaps behind the UI:

1. deadline previews returned no detail rows and used generation time as a
   source cutoff, so an unchanged dataset produced a different snapshot hash;
2. renewal previews loaded the full tenant portfolio and issued repeated
   instruction-history reads per term;
3. portfolio and data-quality freshness was inferred only from the returned
   page, allowing a limited page to hide an unsynchronized record later in the
   authorized result set; and
4. incomplete/truncated result sets did not consistently expose whether their
   summary counts covered the full authorized scope.

The correction extends the existing synchronous readers and report adapter. It
does not introduce a report job, artifact store, scheduler, notification owner,
deadline owner, renewal owner, or portal owner.

## Implemented report boundary

- Portfolio and data-quality reports obtain exact full-scope aggregate counts,
  synchronized-record count, latest record update, and latest successful
  registry cutoff from the canonical access-filtered portfolio query. The
  returned table remains bounded by the requested row limit.
- Deadline control returns one canonical, access-filtered control row per
  visible docket, uses the docket update time as a stable source cutoff, and
  names incomplete counts when another row exists beyond the limit.
- Renewal reporting reads terms through one tenant/access-scoped join, fetches
  at most `limit + 1` candidates, batch-loads deadline/cost/instruction children,
  and omits instruction/reminder history from the report projection. Unfiltered
  output is capped by the request's 200-row maximum. A state-filtered report
  scans at most 1,000 candidates and reports `counts_are_complete=false` and
  `truncated=true` if that ceiling is exceeded; it never presents a partial
  count as complete.
- The canonical renewal workspace retains its existing full-history behavior;
  batching removes the repeated query without moving or duplicating ownership.
- Existing IPLF-055 portal publication/delivery and IPLF-039C signed docket
  control remain the owners for UJ-27 and UJ-59. IPLF-038B consumes those
  surfaces and adds no second publication, delivery, or sign-off workflow.

## Exact row and query-bound proof

- `IpReportPreviewRequest.row_limit` is constrained to 1..200.
- Docket and renewal readers fetch `limit + 1`, return at most `limit`, and set
  an explicit `has_more`/`counts_are_complete` boundary.
- Filtered renewal report candidate work is capped at 1,000 terms.
- A two-term regression observes exactly one SQL `SELECT` mentioning
  `ip_client_instructions`; deadlines and costs are also loaded in set-based
  queries, and report generation skips reminder-history reads.
- The same two-term bounded renewal regression passed against an isolated
  PostgreSQL 17/pgvector database. The dedicated Docker container, network, and
  volume were removed after validation.
