## Duplicate-work reconciliation

The slice adds one type-specific `ip_post_registration_recordals` aggregate.
It extends the existing title-interest and docket-event owners and links to the
existing document, cost, deadline, registry, access, lifecycle and audit
owners. It does not create another proceeding, renewal term, registry client,
document store, cost ledger, deadline engine, permission model or event log.

Cancellation, rectification and non-use remain IPLF-049 proceedings. Renewal
term/instruction state remains IPLF-037. Pending recordals do not replace the
registered-proprietor projection.

## Implemented contract

- Typed list/create/detail/workspace/transaction APIs with tenant and record
  access filtering.
- Assignment, transmission, licence and registered-user party/date validation;
  partial-class scope and opposition-deadline-rule rejection.
- Optimistic recordal and docket-lifecycle concurrency with capability-specific
  review/acceptance/rejection approval.
- Draft, review, filing, acknowledgement, defect, correction, re-filing,
  acceptance, rejection and withdrawal state transitions.
- Party evidence bound to same-docket canonical supporting instruments, plus
  same-docket cost and deadline validation.
- Registry acceptance bound to a confirmed application/registration link,
  an explicitly affected normalized identifier and an exact immutable snapshot
  source URL.
- Pending/filed/recorded/rejected/withdrawn projection through the existing
  title-interest writer, including co-owner and exact-replay handling.
- Append-only recordal event linkage and shared duplicate/backdating controls.
- Additive migration with five-second PostgreSQL lock timeout, empty rollback
  and restore-forward refusal after new legal data is used.
