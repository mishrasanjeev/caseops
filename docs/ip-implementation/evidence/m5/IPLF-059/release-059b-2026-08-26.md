## Notice deadlock closure

The first exact `754789b` production replay, run `32918517371`, exposed a real
PostgreSQL deadlock while a reply attachment upload and its document worker
contended for the actor and Matter rows in inverse order. PR #351 made the
worker fence Membership/User before Matter and added a real PostgreSQL
concurrency regression that proves the upload can acquire Matter and persist
activity while the worker waits on the canonical actor fence.

On release `a3de6fc`, the Notice production window recorded three attachment
POSTs to the same synthetic Matter. All returned HTTP 200 in 0.364, 0.864 and
0.692 seconds. The window contained zero 5xx responses, and the complete
current API revision contained zero `deadlock detected` records.
