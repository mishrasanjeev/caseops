# IPLF-054 local implementation evidence

**Date:** 2026-08-25
**Scope:** IPLF-054A/B licensed Indian Kanoon adapter, source lineage, attribution,
cost controls, source access, and research workflow.

## Ownership and duplicate-work decision

The implementation extends the existing authority corpus, research reports,
provider readiness, provider cost profiles, source actions, billing usage, and
research page. It does not create a second research corpus, report owner, cost
dashboard, provider dashboard, or source-opening mechanism. The former
uncontracted Indian Kanoon public-page scrape was removed from statute
enrichment; only the licensed server-side adapter may call Indian Kanoon.

## Implemented behavior

- All external calls are disabled by default and require the runtime switch,
  pinned HTTPS API host, server-held token, current terms approval and owner,
  approved legal coverage and permitted uses, positive retention/budget limits,
  and approved actual costs for all five operation categories.
- Search, processed document, original document, fragment, metadata, and health
  operations use bounded requests, response-size limits, no redirects, typed
  failure states, bounded caching, stale-cache warnings, and pre-call tenant
  budget checks. Successful uncached calls alone create tenant billing usage.
- Imported sources extend `AuthorityDocument` with publisher, jurisdiction,
  issuing body, source category, authority/binding status, canonical URL,
  content hash, exact source version, retrieval/access state, attribution,
  provider metadata, and legal-review state. Existing authority chunks and
  research reports remain canonical.
- Source changes replace canonical chunks, invalidate linked frozen reports,
  and reset two-person legal review. Two distinct active workspace memberships
  must verify the same content hash.
- Indian Kanoon public URLs open only through the existing authenticated source
  proxy. Licensed authority URLs are approved legal sources but do not become
  official provenance for judges or other official-only records.
- The research page adds a source selector, readiness feedback, bounded query,
  attribution, freshness/cache/cost disclosure, legal-status warnings, and
  protected source links. The existing CaseOps corpus flow remains unchanged.
- The guide, law-firm page, provider catalog/readiness, OpenAPI types, Cloud Run
  default-off environment, data-governance map, and activation runbook are
  updated without claiming a live contract or legal approval.

## Release and activation boundary

- Current state: implemented and locally verified; not yet reviewed, merged,
  deployed, or production verified by this evidence.
- Deploy the additive migration before the API/web revisions. Old revisions are
  compatible with the expanded nullable schema.
- Production remains explicitly default-off. The dated production spec verifies
  readiness, typed refusal, disabled UI, and no paid call.
- If runtime acceptance fails, turn off `INDIAN_KANOON_ENABLED` and roll API/web
  traffic back to the prior immutable release. Do not downgrade after licensed
  source or report-lineage data exists; the migration refuses destructive loss.
- Contract execution, credentials, legal approval, live-provider acceptance,
  source-coverage acceptance, and law-firm UAT remain independent external work.
