## PostgreSQL-only gate correction

PR 399's first hosted PostgreSQL validation exposed a local-gate omission after
the exact browser harness had passed. The PostgreSQL savepoint regression
expected a poison event to be terminal after one attempt while invoking the
worker's default three-attempt retry policy. The production worker correctly
persisted the event as `pending` with backoff, so the assertion failed.

The regression now explicitly requests `max_attempts=1` for its terminal-state
case and verifies the durable attempt count, absent retry timestamp, PostgreSQL
`DataError`, successful sibling event, and completed revocation. The formerly
failing test passed against a fresh local pgvector/PostgreSQL 17 container, then
the complete PostgreSQL marker suite passed 108/108 in 82 seconds.

`scripts/verify-docker.ps1` now supplies the isolated Compose database to the
host PostgreSQL fixtures and runs all `test_postgres_validation.py` PostgreSQL
cases after both index-health gates and before Playwright. A future candidate
therefore cannot reach hosted CI with a PostgreSQL-only failure hidden behind
the normal SQLite environment skip.

## Implemented operational controls

- Projection events are tenant-bounded, indexed, retryable at most three times,
  and preserve content-minimized terminal evidence.
- The five-minute Cloud Run maintenance job caps tenant/event/rebuild work,
  blocks on lag or integrity failure, logs a correlation ID, and has a
  reconciled log-based production alert and operator runbook.
- Approved private-index disposition rechecks retention and legal holds,
  emits the canonical tenant tombstone, verifies neutralized projections, and
  records a durable local receipt or explicit provider contractual-delay
  exception. A later rebuild cannot resurrect disposed content.
- Streaming, autocomplete, count, Assistant answers/citations/exports,
  intelligent-review reports and portal document access all reauthorize at
  delivery and fail closed after access, source, lifecycle or epoch change.
