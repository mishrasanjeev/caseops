AuthorityDocument, JudgeDecisionIndex, source-action, capability, audit, and

## Safety and data assertions

- Raw `judges_json` coincidence is never used as a profile mapping fallback.
- Canonical authority pages expose citation, date, court/bench, source action,
  confidence, status, raw evidence, role, and analytics eligibility.
- Cursor pagination is opaque and keyset-based; filters and malformed cursors
  fail closed.
- Initial profiles include the first authority page, avoiding a duplicate
  browser request; later pages append correctly to that embedded page.
- Court judge listings use one grouped count query rather than per-judge scans.
- Only analytics-eligible mappings feed descriptive profile aggregates.
- UI and tests prohibit personality, bias, emotion, outcome probability,
  favoritism, or judge-shopping claims. Counsel appearance remains outside the
  judge-mapping domain.
- Curator controls require `court_sync:run`; non-curators receive a read-only
  audit catalog.

## Defect found during acceptance

The first browser run proved that `Load more` replaced the ten authorities
embedded in the profile with the final two because append mode only recognized
an explicit paginated state. The UI now treats the embedded page as the initial
pagination state. A component regression and the unchanged E2E count assertion
prove `10 shown of 12` becomes `12 shown of 12`.
