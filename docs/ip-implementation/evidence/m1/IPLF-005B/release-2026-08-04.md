## Implemented UJ-16 workflow

### Seven explicit search modes

The research API and UI now support keyword, contextual, exact citation, party,
court, judge, and Act/section modes. Keyword and contextual modes retain hybrid
retrieval. Structured modes narrow candidates using canonical extracted
metadata, then use the same ranking, citation-treatment enrichment, source
action, readability, language, forum, court, document-type, and pagination
pipeline.

Candidate text includes the canonical neutral citation, case reference, party,
judge/bench, and cited-section metadata. Result cards show publisher, case
reference, neutral citation, relevant passage, treatment state, and an
explainable relevance reason. The reason describes observable match signals and
known treatment; it does not assert likely success.

### Typed outcomes and measured corpus scope

The API distinguishes:

- `results_found`;
- `no_matching_documents`;
- `corpus_unavailable`;
- `index_stale`;
- `provider_unavailable`;
- `permission_denied`;
- `query_invalid`;
- `request_timed_out`;
- `offset_out_of_range`; and
- `unreadable_filtered`.

The first five are serialized response outcomes where the server can determine
them. The remaining request-layer outcomes are mapped by the web client from
the authoritative HTTP/browser failure. Zero rows are not presented as “no
matches” when the corpus is absent or index evidence is stale.

Each search response carries measured corpus coverage: document, chunk, and
embedded-chunk counts; forum counts; latest ingest/index timestamps; index
state; and a human-readable scope summary. Index state is derived from actual
corpus/chunk presence and the latest ingestion result. No arbitrary age or
seven-day waiting rule was introduced.

The browser aborts a search after 20 seconds. Submitted criteria are frozen as
the committed result context, while draft controls remain editable. Editing a
draft does not relabel the displayed result set. Recovery copy preserves the
last committed query for timeout, provider, permission, validation, stale
index, unavailable corpus, unreadable documents, pagination drift, and generic
network failures.

### Immutable saved research

An authorized user can save a result set as an immutable
`AuthorityResearchReport`. The server reloads every requested result ID from the
canonical corpus and rejects missing records instead of trusting client-supplied
titles, citations, publishers, or destinations. It then freezes canonical
source metadata, search criteria, generation time, and analysis version
`authority-search-v3-2026-08-04`.

Reports are company-scoped on create and list. The audit event records actor,
company, report identity, mode, result count, analysis version, and a normalized
query SHA-256; it does not copy the raw query into audit metadata. The report
itself retains the query because that is the user-requested immutable research
artifact. Saved reports show their frozen sources and offer a **Refine search**
link back to the live research workspace.

### Narrow-viewport acceptance

All seven mode actions are in a wrapping, full-width, explicitly shrinkable
group. The query row and Save report action become full-width on mobile. The
dated 360 × 800 Playwright journey asserts that every mode action is visible,
the document has no material horizontal overflow, the committed result remains
unchanged while a draft is edited, typed corpus-unavailable recovery appears,
an exact-citation result renders its publisher/citation/relevance evidence, and
the exact immutable report payload is submitted.

## Additive migration and compatibility

Migration `20260804_0002` creates only `authority_research_reports` plus
company/creator indexes and foreign keys. It has no data rewrite or backfill.
The candidate parent is `20260802_0001`; before release it must be rebased to the
then-current IPLF-004B migration head so Alembic remains linear.

The new API fields are additive. Existing keyword/contextual callers retain
their modes, filters, and pagination. The old ambiguous `no_results` value is
replaced by typed, truthful zero-result states and the existing browser
regression was updated to accept the appropriate visible state.

Rollback is explicit: application rollback may leave the additive table in
place because older code does not read it. A database downgrade drops only the
new indexes and report table; it is destructive to saved reports and therefore
is not the routine production rollback path.

## Security and legal-integrity controls

- Search and report endpoints remain capability-gated and tenant scoped.
- The server, not the client, determines report source/citation metadata.
- Cross-tenant reports are never returned.
- Audit stores only the normalized query hash, not the raw research query.
- Provider tokens are neither accepted in payloads nor printed by the runner.
- Corpus absence, stale index evidence, provider failure, unreadable documents,
  and permission failure remain visible and distinct.
- No unavailable source is replaced silently and no result is labelled official
  merely because a URL exists.
- No legal filing, external message, provider purchase, legal advice, or
  irreversible production action was performed.
