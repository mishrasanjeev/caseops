## Bounded scope and ownership

IPLF-004A implements the backend foundation for safe source proxying, source-open
audit, and link-defect/health reporting. It extends the source owners established by
IPLF-003A through IPLF-003C:

- `AuthorityDocument`, `StatuteSection`, and `JudgeAppointment` remain the canonical
  legal-source records. The new endpoint resolves their current values at open time;
- `inspect_source_action` remains the single source-state classifier and redirect
  allow-list boundary;
- the existing unified `AuditEvent` ledger remains the audit owner; and
- the new tenant-scoped `SourceLinkReport` is the canonical queue record for a
  user-reported broken, wrong, denied, stale, or otherwise defective link.

No second authority/statute/judge master, provider credential store, legal-content
writer, or provider-operations subsystem was introduced. The compatibility
`/api/source-actions/open?url=...` route remains available for already-issued links;
all updated canonical serializers issue the opaque resource-backed route. Retirement
of the compatibility route is deferred to a separately evidenced mixed-revision
cutover, not silently performed in this foundation slice.

This is an administrative foundation slice with no direct requirement or journey
allocation. IPLF-004B retains the reciprocal `LEGAL-SRC`, `SRC`, `TRUST-BA`,
`TRUST-RSCH`, and UJ-17 workflow allocations. This document therefore does not claim
those families complete.

## Implemented backend contract

### Opaque, revalidated source opening

Canonical API serializers now issue URLs of the form:

`/api/source-actions/targets/{target_type}/{target_id}/open`

Supported target types are `authority_document`, `statute_section`, and
`judge_appointment`. The browser request contains only the resource type and opaque
record identifier. On each request the authenticated, capability-gated API:

1. resolves the canonical record server-side;
2. derives the current source state and source version;
3. refuses missing, unverified, blocked, or quarantined sources with a typed
   `X-Source-State` response;
4. re-applies the redirect allow-list immediately before redirecting;
5. records the open attempt in the unified audit ledger; and
6. returns a temporary no-store redirect with `Referrer-Policy: no-referrer` only
   for an available destination.

The raw destination is not present in the resource-backed request URL. Existing
authority search, saved research, court-authority analytics, judge appointment,
statute list, and statute detail responses all use the opaque action contract.

### Audit evidence without raw destinations

`source_access.opened` audit events capture target type/id, origin surface,
permission decision, destination class, source state/version, provider class,
outcome, and `source_reference_sha256`. They do not copy the raw source URL into the
audit metadata. Both successful redirects and fail-closed source-state outcomes are
recorded.

### Tenant defect and health queue

`POST /api/source-actions/reports` accepts a canonical target, origin surface, issue
type, and an optional bounded description. It resolves the current target rather
than trusting a client-supplied destination, then atomically creates:

- one tenant-scoped `SourceLinkReport` in `queued` state; and
- one `source_access.defect_reported` audit event with
  `health_check_requested=true`.

The queue row stores company and reporting-membership ownership, target identity,
source state, destination class, issue metadata, and only a SHA-256 fingerprint of
the source reference. There is no raw destination column. Unknown targets fail
closed with 404 and cannot manufacture queue records.

## Additive data migration

Migration `20260803_0001_source_link_reports` is linear from `20260802_0001` and
creates only the `source_link_reports` table plus its constraints and indexes. It
adds foreign keys to company and membership ownership and validates the target,
origin, issue, source-state, destination-class, status, and hash shapes.

No existing row is rewritten and no backfill is required. The downgrade drops only
this additive table and its indexes. Rollback of application revisions therefore
leaves existing authority, statute, judge, and annotation data untouched; the unused
additive table may remain in place during application rollback.

## Security and privacy observations

- Provider credentials and bearer tokens are never returned to browser JavaScript.
- Canonical open actions no longer disclose raw public destinations in their request
  query string.
- Destination allow-list validation occurs again at the moment of redirect, so a
  changed canonical record cannot bypass source-state inspection.
- Unverified, blocked, missing, quarantined, unsafe, and unknown targets fail closed.
- Redirect responses are temporary, no-store, and no-referrer.
- Audit and report records store a source fingerprint rather than the raw URL.
- Reports are tenant-owned and actor-attributed through active membership context.
- This slice performs no external legal-source fetch, publication, message, legal
  filing, approval, or irreversible provider action.
