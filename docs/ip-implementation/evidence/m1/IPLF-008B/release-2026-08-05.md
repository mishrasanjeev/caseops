## Scope and canonical ownership

IPLF-008B completes the repository-controlled production acceptance path for
TRACK-01 through TRACK-14. It extends the existing `TrackedCase`, bookmark,
provider-operation/cost ledger, support matrix, source proxy, production
Playwright workflow, and release sign-off template. It does not add a parallel
tracking table, scheduler, provider ledger, notification dispatcher, source
store, or deployment system.

The release canary is an authenticated `workspace:admin` operation on one
explicitly tagged QA bookmark. The endpoint requires the full exact SHA exposed
by the serving API, serializes execution under the tracked-case row lock, and
uses the unique company/correlation constraint `release:<40-character SHA>`.
Consequently one company/release pair performs at most one provider refresh,
while retries return the already recorded costed operation and source evidence.

## Implemented production contract

- `POST /api/case-tracking/bookmarks/{bookmark_id}/release-smoke` rejects an
  abbreviated, stale, or non-serving SHA and rejects ordinary tenant bookmarks.
- The canary retains provider health, support-matrix, quarantine, poison-record,
  disposed-Matter, source-boundary, audit, snapshot, normalized-diff, and cost
  controls. It bypasses only the ordinary end-user daily refresh quota because
  it has its own once-per-exact-release bound.
- Provider success/no-change, freshness, last attempted/successful state,
  correlated operation, immutable snapshot, cost/currency, audit event, and a
  protected provider source update are returned as one fail-closed proof.
- The dated production spec compares API and web release identities, signs into
  the dedicated QA tenant, reuses an approved tagged bookmark or bootstraps one
  from `CASEOPS_QA_TRACKED_CASE_CNR`, executes the canary, downloads non-empty
  bearer-authenticated source content through CaseOps, and verifies the real
  case-tracking surface at 360 px.
- The QA fixture is notification-disabled and synthetic/control-plane scoped.
  The intended CNR is a public example from the provider's API documentation;
  no real client data or client communication is used.
- The source action must be visible, resolve to the exact CaseOps API proxy path,
  open in a protected new tab, and fit the narrow viewport together with every
  grouped bookmark action. DOM presence alone is not accepted.
- The expanded release template records requirements/journeys, ownership and
  duplicate analysis, capabilities, schema/migration state, threats, exact
  build identity, test inventory, documentation, external approvals, and
  production evidence. It contains no arbitrary elapsed-day release gate.
