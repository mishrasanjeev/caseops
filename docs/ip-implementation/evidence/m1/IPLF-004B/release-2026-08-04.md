## Implemented UJ-17 workflow

### Public and provider-backed references

Every canonical source action now carries `target_type` and `target_id` in addition
to its typed source state. Selecting an available action sends only that identity
and the enumerated origin surface to the authenticated API. The API resolves the
current record on every click, so an expired or replaced URL is refreshed from the
canonical server-side record before access. It then revalidates the current scheme,
host, credentials, port, quarantine, and verification state before issuing a
temporary no-store/no-referrer redirect.

The browser never receives a provider bearer token. The origin surface is correlated
as one of `research`, `saved_research`, `judge_profile`, `uploaded_case_analysis`,
`intelligent_review`, `statute`, or `other`; it is not a free-form query or secret.

### Protected uploaded Matter documents

`matter_attachment` is now a canonical source target. Resolution loads the parent
Matter, verifies company ownership, and runs the existing Matter/ethical-wall access
policy. An authorized user receives only an internal authenticated attachment
download redirect; that existing endpoint reauthorizes before streaming bytes. A
different tenant receives 404 for both open and defect-report operations. No storage
key, signed object URL, document text, or credential is placed in the source action.

Matter File Q&A and intelligent-review serializers now issue the same opaque
`matter_attachment` action instead of exposing the internal download route as the
click target. Their original citation/snippet metadata remains unchanged.

### Failed, stale, denied, and quarantined sources

Unavailable canonical records keep citation metadata and render a typed non-link
state. A failed open atomically records `source_access.opened` with a failed outcome
and idempotently queues a tenant `SourceLinkReport` health check. Repeated attempts
for the same tenant, target, origin, issue class, and active queue state reuse the
open report rather than creating a report storm.

The automatic issue mapping is deterministic:

| Source state | Queue issue |
| --- | --- |
| `missing` | `broken` |
| `unverified` | `stale` |
| `blocked` | `access_denied` |
| `quarantined` | `wrong_document` |

Both the source-open and defect audit records correlate actor, company, canonical
target, origin, source version, provider class, destination class, typed state, and
outcome. They store only `source_reference_sha256`; raw destinations and credentials
are not copied into audit or queue metadata.

### User defect reporting

Available and unavailable canonical actions expose a responsive **Report** control.
The dialog accepts a typed issue and optional 1,000-character description, sends it
through the cookie/CSRF-aware API client, prevents duplicate submission while
pending, reports success or failure, and resets only after a successful queue write.
The citation stays visible while the link is reviewed.

The grouped Open source/Report control is explicitly `min-w-0`, full-width and
wrapping on narrow viewports, then content-width on larger screens. The saved-result
header was likewise made columnar on mobile and row-oriented only from the small
breakpoint. A dated 360 × 800 browser test caught and proved the repair of a real
16-pixel horizontal overflow before this checkpoint was recorded.

## Security and external-gate truth

- Provider credentials remain server-side and no bearer token is placed in a URL,
  copied link, source action, report, or audit event.
- Matter storage keys and signed storage URLs are never exposed by the source-action
  contract.
- Canonical targets are re-resolved and safety checked at click/report time; the API
  does not trust a client destination.
- Source and Matter access remain capability- and record-policy-gated. Cross-tenant
  existence is concealed with 404.
- Failed sources do not silently substitute another provider or fabricate coverage.
- This slice does not fetch, republish, cache, or enable Indian Kanoon or another
  licensed corpus. Provider terms, credentials, permitted uses, attribution, quotas,
  retention, support owner, and kill-switch approval remain genuine external release
  gates for those adapters.
- No legal filing, legal-source approval, external message, provider purchase, or
  irreversible external action was performed.
