## Scope and ownership

IPLF-008A is the administrative foundation slice of IPLF-008. It extends the
canonical `scripts/deploy-prod.sh`, `.github/workflows/prod-verify.yml`, API health
router, and Next.js application. It does not introduce a second deployment tool,
test runner, status store, scheduler, or release database.

The slice closes the specific identity race in which a push-triggered production
suite could start before the corresponding images served traffic. Source-tree CI
and a production test are no longer sufficient unless the API, web, checked-out
test source, and expected release all resolve to the same exact 40-character Git
revision.

## Implemented contract

- The API publishes `/api/build` with `service`, exact `release_sha`, and Cloud Run
  `revision`. Missing or abbreviated revisions return `unavailable` rather than an
  inferred or optimistic identity.
- The web service publishes `/api/release-identity` with the same fail-closed
  contract and disables response caching.
- The canonical deploy injects `CASEOPS_RELEASE_SHA` from the verified full
  `HEAD_SHA` into both Cloud Run services while continuing to pin recurring jobs
  to the immutable API digest.
- `scripts/verify_deployed_release.py` rejects malformed identities, mixed API/web
  releases, stale releases, abbreviated expected SHAs, and missing runtime
  revisions. It can wait for a bounded deployment convergence window and writes
  exact release/revision values to GitHub step output.
- The production workflow first verifies the serving pair, then checks out the
  exact serving commit and asserts local `HEAD` equality before installing or
  running Playwright. Push/manual releases wait for the expected SHA; scheduled
  drift runs discover and check out the current common serving SHA.
- No elapsed-day requirement is used. The bounded wait exists only to cover the
  active deployment transaction and fails closed if production never converges.

## Security and data impact

The identity endpoints expose only public build provenance: service name, source
revision, and Cloud Run revision. They expose no environment values, tenant data,
configuration, credentials, image registry tokens, or secret references. There is
no schema migration, backfill, tenant mutation, external provider call, or legal
side effect in this slice.

script; the added public routes can be removed without data repair. During rollout,
the first push workflow intentionally waits until both newly deployed services
publish the new identity. If only one service updates, production verification
remains red and Playwright does not run against a mixed release.
