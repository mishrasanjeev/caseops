## Bounded scope and ownership

IPLF-003A established the canonical source-state/open contract and safe redirect
boundary. IPLF-003B rendered that contract on research results, uploaded Matter
documents, litigation-intelligence review, and judge surfaces. IPLF-003C closes the
remaining saved-research surface gap and adds explicit reusable-component and
narrow-viewport exception proof. It extends, rather than duplicates, these owners:

- `AuthorityDocument.source` and `AuthorityDocument.source_reference` remain the
  authority source-of-truth;
- the existing authority annotation service remains the sole saved-research writer;
- `inspect_source_action` remains the sole server-side serializer of source action
  state; and
- `SourceAction` remains the shared user-visible renderer for available, missing,
  unverified, blocked, and quarantined states.

The change introduces no table, migration, background writer, provider credential,
or legal-source content operation. Source proxy health, defect reporting, refresh,
and provider-operation orchestration remain allocated to the later IPLF-004 and
provider-operation slices; this slice does not create a competing implementation.

## Implemented behavior

### Saved research API contract

`GET /api/authorities/annotations` now returns the immutable authority source context
alongside each saved annotation:

- `authority_source` identifies the publisher/provider classification stored on the
  saved authority;
- `authority_source_reference` preserves the original reference; and
- `authority_source_action` supplies the typed, fail-closed action produced by the
  canonical source-action service.

The source contract is derived at read time from the referenced authority, so saving
or archiving an annotation cannot manufacture a second source record or silently
rewrite the authority. Tenant scoping and the existing annotation capability checks
are unchanged.

### Saved research user surface

The saved-research card no longer labels an internal search-by-title navigation as
“Open.” It now renders the same `SourceAction` used by the other PRD-named source
surfaces, keeps publisher and citation metadata visible, and shows typed non-link
states when the server refuses to issue an open URL. This prevents an unavailable or
unverified source from looking actionable while preserving the citation a lawyer
needs for recovery and verification.

The generated OpenAPI client and handwritten web endpoint type were updated together,
so backend serialization and frontend consumption cannot drift silently.

### Shared renderer hardening

Dedicated component tests establish that an available action:

- uses only the server-issued source route;
- opens in a new browsing context when instructed;
- sends `rel="noopener noreferrer"`; and
- uses `Referrer-Policy: no-referrer` at the browser link boundary.

Missing, unverified, blocked, and quarantined actions render as typed status text and
never render an open link.

## Security and privacy observations

- The browser receives no provider bearer token or credential.
- The UI does not convert raw `source_reference` into a link; it consumes only the
  server-issued `open_url` when state is `available`.
- Unverified, blocked, missing, and quarantined records fail closed.
- Available links suppress referrer disclosure and reverse-tabnabbing.
- The saved annotation body, query terms, and source reference are not added to a new
  telemetry or logging channel by this change.
- The change does not fetch, publish, or modify legal source text.
