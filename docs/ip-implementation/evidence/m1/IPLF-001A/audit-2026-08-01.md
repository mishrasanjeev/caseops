## Additional drift and safety findings

1. Cloud Scheduler error logs on `2026-07-29` through `2026-08-01` repeatedly
   record `PERMISSION_DENIED` for legal-update, case-tracking, and authority
   metadata. The weekly DB-index scheduler last recorded the same code on
   `2026-07-26`. An enabled flag is therefore not health evidence.
2. The production API serves commit/tag `fd1238c`, which is an ancestor of
   current `main` (`cadb46d`). This audit does not claim current `main` is
   deployed.
3. Legal-update, case-tracking, and reminders match the serving API digest.
   Activity-report does not. Its digest was updated in Artifact Registry on
   `2026-07-31`, has no retained tag, and was not tied to a verified source
   revision by available read-only evidence.
4. Authority-metadata and DB-index-health use mutable commit tags rather than
   immutable digest references and are omitted from both recurring image
   refresh and scheduler/IAM convergence code.
5. `infra/cloudrun/deploy.ps1` would provision `caseops-document-worker` and
   `caseops-document-worker-trigger`, but the canonical production deploy test
   explicitly treats that component as optional and absent from production.
   This is a declared-contract inconsistency, not evidence that the optional
   worker should be deployed.
6. The reminder job's exit `0` proves only worker execution. It does not prove
   provider submission, delivery, or recipient receipt.
7. A field-limited log inspection found that the activity-report job writes the
   generated tenant report payload to Cloud Logging. Tenant identifiers/names
   were deliberately not copied here. This conflicts with the PRD's redacted
   operator-log requirement and needs a separate safe-logging fix before M1
   acceptance.

## Exact remediation plan for IPLF-001B

No step below was executed in `IPLF-001A`.

1. Define one version-controlled scheduler inventory containing scheduler name,
   job target, cadence, timezone, OAuth identity, required runtime image policy,
   canary mode, and ownership. Include legal-update, case-tracking,
   authority-metadata, DB-index-health, activity-report, and reminders. Mark the
   document worker explicitly optional rather than inferring production need.
2. Make `caseops-scheduler-invoker@perfect-period-305406.iam.gserviceaccount.com`
   the OAuth caller for every required scheduler. Grant only that principal
   job-level `roles/run.invoker` (or the approved least-privilege equivalent)
   on each target. Keep `caseops-runtime@...` only as the job runtime identity.
3. Reconcile case tracking to the approved `16:30` `Asia/Kolkata` window. Use an
   expand/switch rollback: create/update the canonical scheduler, verify target
   and canary, pause the midnight scheduler, observe, then retire it only after
   the rollback window. Do not run provider calls outside the configured window.
4. Extend the release path to pin every required API-backed recurring job to the
   exact immutable API digest. Fail release on any missing job, mutable tag,
   digest mismatch, scheduler error status, identity mismatch, target mismatch,
   timezone/schedule mismatch, or missing per-job binding.
5. Add a read-only drift verifier with unit fixtures for healthy, missing,
   paused, wrong-target, wrong-identity, wrong-timezone, permission-denied,
   stale-success, mutable-image, and digest-mismatch cases. Run it in the
   release workflow after deployment; CI tests its parser with fixtures and
   does not require production credentials.
6. Stop the activity-report worker from logging report content. Log only safe
   correlation, segment/account counts, output/delivery status, duration, and
   error class. Add a regression test that rejects tenant names, identifiers,
   email addresses, and report payloads in logs.
7. Under action-scoped production approval, apply IAM/scheduler/image changes,
   run bounded canaries that do not send uncontrolled messages or spend
   provider quota, then verify the exact executions and safe logs.
8. Keep M1 blocked until every required scheduled window is green for seven
   consecutive days and the exact deployed revision/image evidence is attached.
