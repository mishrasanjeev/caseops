## Delivered boundary

- Extends the existing tenant-owned `ip_proceedings` record with constrained intake origin, role-aware stage-template version, and explicit opposition-number-pending state.
- Keeps `ip_identifiers` as the only identifier owner. An optional opposition number is created atomically against `proceeding_id`; it can never occupy the linked trademark application's identifier slot.
- Adds the canonical opposition stages from PRD Section 12.2 and an optimistic-concurrency transition API requiring `ip:approve`.
- Reuses `ip_docket_events` as the one legal-history owner. The generic event route invokes the same opposition guard, so it cannot bypass number, stage, evidence, closure, or version checks.
- Requires a confirmed current opposition number and linked application before leaving `draft`. A pending Registry allocation remains explicit and fail-closed.
- Requires authority for skipped, waived, extended, and superseded events. Closure additionally requires outcome, effective date, source, evidence, and authorized confirmation.
- Migration `20260823_0001` adds only three deterministic metadata columns and five constraints, and makes marked opposition-stage events append-only in SQLite and PostgreSQL. It does not duplicate documents, deadlines, hearings, tasks, billing, notifications, Matter lifecycle, or registry-provider state.

## Duplicate-work review

`IPLF-040A` does not create a second proceeding, timeline, identifier, audit, access, or workflow-definition subsystem. It extends these existing owners:

| Concern | Canonical owner retained |
| --- | --- |
| Proceeding identity/current stage | `ip_proceedings` |
| Application and opposition numbers | `ip_identifiers` |
| Immutable stage history/evidence | `ip_docket_events` |
| Tenant and restricted-record access | existing IP docket access guard |
| Audit | shared `audit_events` writer |
| Tasks, hearings, deadlines, documents, communications, billing | existing shared/IP bounded owners; unchanged |

The complete applicant/opponent workspace, pleadings, evidence packages, challenged scope, relied-on rights, service, hearings, orders, appeals, reports, and UJ-12/UJ-13 browser journeys remain explicitly assigned to `IPLF-040B` and later M4 slices.
